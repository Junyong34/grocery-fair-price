# 시세 카탈로그 확장: 수천 개 항목으로 가는 구조

Status: needs-triage
작성일: 2026-11-09 (사용자와 문답으로 정함)
대체: [catalog-evolution](../catalog-evolution/spec.md)의 "코드 원본·어드민 없음" 결정(02·03·05). 그 계획의 01(규격별 판정)·04(제철 매핑)·06(판정 묶음 공개)은 이 문서의 티켓으로 이어 받는다.

## 목적

공공 API로 이미 받고 있는 식재료·상품 데이터를 사람이 하나씩 코드에 적지 않아도 화면에 올린다. 평소가가 없어도 최근 시세는 보여 준다. 항목 수를 지금의 품종 136개에서 수천 개까지 점차 늘린다. 이번 단계에서는 소매 출처 3개(KAMIS·축평원·참가격) 안에서 구조를 잡고, 공공 API는 나중에 하나씩 더 붙인다.

## 지금 상태 (2026-11-09 확인)

- **화면에 나오는 조건.** 적재 때 원천 키가 카탈로그(`packages/price-ingest/src/catalog/varieties.ts`의 규격별 `kamis`·`ekape`·`chamga` 코드, 색인은 `match.ts`)에 없으면, 관측값은 `variety_id = null`로 쌓이고 `source_code_map`은 `pending`이 된다. 시세 요약(`daily_quote`)은 매핑된 관측값으로만 만들고, 판정 묶음(`judgment/cli.ts`)은 `variety.status = 'active'`이면서 기본 규격(`spec.is_default`)인 것만 쓴다. 화면은 판정 묶음만 읽는다(ADR 0004). 그래서 pending은 시세 계산 단계에서 이미 빠진다.
- **평소가가 없어도 이미 보여 준다.** 판정 127행 중 48행이 '판정 전'으로 최근 시세만 나간다(10-30). 항목을 늘리는 데 막히는 지점은 평소가가 아니라 **카탈로그를 손으로 적어야 한다는 것**이다.
- **지금 출처의 한계** ([item-inventory.md](../../grocery-price/docs/30-data/sources/item-inventory.md), 10-19): KAMIS 소매 94품목·186조합, 축평원 약 25조합, 참가격 식품 457상품(신선 71, 가공 386). 원천 키는 다 합쳐 약 670개다. 식재료로 묶으면 200~250개가 상한이고, 가공식품 상품을 더해야 700개 안팎이 된다. **수천 개는 출처를 더 붙여야 닿는다.**
- 참가격은 자체 상품 분류(AL: 대분류 3, 중분류 14, 소분류 171)를 준다. 지금은 품종 매핑의 입력으로만 쓴다([chamgagyeok.md 4-1](../../grocery-price/docs/30-data/sources/chamgagyeok.md)).

## 결정 (2026-11-09)

| 주제          | 결정                                                                                          | 이유·조건                                                                                                          |
| ------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 개수 단위     | 식재료(품종) + **가공식품 상품**을 함께 센다                                                  | 출처를 더 붙이면 수천 개까지 간다                                                                                  |
| 출처          | 이번 단계는 **소매 3개 유지**. 공공 API는 구조가 잡힌 뒤 하나씩 추가                          | 판정의 뜻(마트 소매가 기준)을 지킨다. 도매 경락가는 나중에 따로 정한다                                             |
| 가공식품 화면 | **상품 하나 = 한 페이지.** 최근 조사일 가격과 업태·판매처별 비교. 판정은 내지 않는다          | 참가격은 2주에 한 번 조사해 평소가를 만들기 어렵다. 쓸모가 큰 건 "어디가 싼지"다                                   |
| 카탈로그 원본 | 코드(`varieties.ts`)에서 **DB 표**로 옮긴다                                                   | 수천 개를 AI 제안과 일괄 승인으로 다루면 커밋→적용 흐름이 병목이 된다(catalog-evolution이 스스로 적은 재검토 조건) |
| 어드민        | **로컬 전용** `/admin/catalog`(`pnpm dev`, 소유자 접속). 묶기·추가·제거·승인                  | 로그인·권한·CSRF가 필요 없다. 배포된 웹은 계속 `web_reader`로 읽기만 한다(ADR 0002)                                |
| AI 제안       | **로컬 에이전트(Claude Code)**가 pending을 읽고 제안을 쓴다. 승인 전에는 화면에 나오지 않는다 | API 키·비용이 없다. 대신 사람이 돌려야 한다                                                                        |
| 카테고리      | **우리 카테고리 체계 + 출처 분류 대응표.** 가공식품용 카테고리를 더한다                       | 출처를 늘려도 대응표만 늘린다                                                                                      |
| DB 용량       | **Supabase Pro로 전환**                                                                       | 일일 백업이 함께 켜진다. DB 원본 전환의 선행 조건이다                                                              |
| 순서          | **확장 먼저.** 안정화는 선행 3개만 앞에 두고 나머지는 뒤로                                    | 아래 "작업 순서"                                                                                                   |

### 반대 의견으로 남겨 둔 것

- **DB 원본은 백업 없이는 하지 않는다.** 운영자가 묶고 승인한 결정은 원천 데이터로 다시 만들 수 없다. Pro 전환(일일 백업)이 [04](issues/04-catalog-db-source.md)보다 먼저다.
- **확장 먼저의 위험.** 장애 처리(`ingest-foundation/05`의 상황별 테스트)·빈 날 메우기·재등록 감시를 뒤로 미룬다. 수집이 조용히 비면 알림은 오지만 자동으로 메워지지 않는다. 그동안은 09:30 다시 받기와 주간 14일 다시 받기로 버틴다.

## 용어 영향

[GLOSSARY.md](../../grocery-price/GLOSSARY.md)의 **상품**은 "하나의 품종에 속한다"고 정의한다. 가공식품 상품은 품종 없이 화면에 나온다. 이 정의와 **카테고리**(장보기 동선 기준 6개)를 [01](issues/01-glossary-adr.md)에서 고친다.

## 범위 밖

- 도매 경락가·산지가 출처 (소매 판정과 뜻이 달라 따로 정한다)
- 배포된 어드민과 로그인
- 수집 배치 안에서 AI를 자동으로 부르는 것 (나중에 로컬 흐름이 병목이 되면 다시 본다)
- 가공식품의 평소가 판정
- 사용자 제보 (로드맵 E2)
