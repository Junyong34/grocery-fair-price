# 06. 구간 줄 적용

Status: resolved
Type: task (AFK)
Blocked by: 05

## 목적

화면마다 탭 줄(또는 헤더) 아래에 고정할 구간 줄을 넣는다. 본문에서 다른 스티키 구간에 들어가면 구간 줄만 바꾼다(spec 4-1 표).

## 할 일

- [x] 구간 줄 슬롯 API: 구간 컴포넌트가 자기 줄을 등록하고, IntersectionObserver로 화면에 들어온 구간의 줄을 보인다. 높이 40px, 칩의 누르는 영역 44px.
- [x] 화면별 적용
  - 2b 그 달: 달 칩(지금 `month-timeline`)을 구간 줄로 고정한다.
  - 3a 계절 상세: 계절 칩
  - 1g: 명절 칩(`festival-chips`)
  - 1h: 보기 필터 줄(월별 ▾ + 달 칩). 지금의 월별/계절별 세그먼트와 달 칩을 한 줄로 합친다.
  - P3: 섹션 칩(시세 · 어디서 · 왜 · 내 가격). 누르면 그 섹션으로 스크롤한다. 섹션에 `id`를 붙인다.
  - P1: 본문 검색 입력이 화면 밖으로 지나가면 검색 입력 줄이 나타난다(누르면 `/search`).
- [x] 2a는 구간 줄이 없다. 월 레일은 지금처럼 측면에 둔다.

## 완료 기준

- 루트 `pnpm typecheck` · `pnpm lint` · `pnpm test` 통과
- 375 · 1280에서 확인한다:
  - 각 화면에서 스크롤해도 구간 줄이 따라온다.
  - 칩을 누르면 맞는 곳으로 이동한다.
  - P3 섹션 칩 활성 표시가 스크롤 위치를 따른다.
  - 콘솔 오류가 없다.

## Answer

2026-11-02. 지금 2b 달 타임라인(110px)과 1g 명절 칩(133px)은 그대로 고정하기에 너무 크다. 그래서 원래 줄은 본문에 두고, 그 줄(id)이 고정 줄 아래로 지나가면 40px 얇은 칩 줄이 나타나게 했다(`shared/shell/section-row.tsx`의 `SectionRow` · `SectionChip`). 위치는 `--shell-top`(+ 탭 줄 `--tabs-h` 60/66px)을 따른다.

- 화면별 적용
  - 2b 그 달: `month-chip-row`(1~12월, 지금 달을 가운데로)
  - 1g: `festival-chip-row`
  - P3: `section-chips`(시세 · 어디서 · 왜, 스크롤 위치 표시, 누르면 그 섹션으로)
  - P1: `search-row`(본문 검색창이 지나가면)
- 화면에 구간이 하나씩뿐이라 IntersectionObserver 교체 장치는 만들지 않았다. 원래 줄이 보이는지만 rAF 스크롤 측정으로 본다.
- 1h는 이미 필터 묶음이 `sticky top-14`라 그대로 둔다(pinned 헤더).
- 3a 계절 상세에는 계절 칩 줄이 없어 이번에 더하지 않았다.
- 함정: 서버 컴포넌트(detail-view, home-view)가 "use client" 모듈에서 가져온 상수는 클라이언트 참조라 값이 비었다. 그래서 id 상수를 `section-ids.ts` · `search-id.ts`로 뺐다.
- 확인한 것: 375에서 2b(탭 아래 top 60, 11월 강조), 1g, P3(헤더 아래 top 56, 스크롤에 따라 "왜" 활성)를 봤다. 콘솔 오류는 0건이다. P1은 목록이 짧아 검색창이 헤더 밖으로 나가지 않아, 실제로 줄이 나타나는 장면은 보지 못했다.
