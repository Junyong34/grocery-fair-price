# 01. 품종 리스트업

Status: ready-for-human
Type: grilling
Blocked by: p2-data-source-spec/13

## 목적

서비스가 판정할 **품종**의 목록을 만든다. 고기, 채소, 과일, 수산, 계란·유제품, 라면·가공식품, 양념 등 장보기에서 쓰는 식자재를 카테고리별로 나열하고, 각 품종이 어느 출처의 어느 코드로 시세를 받는지 연결한다.

초안은 에이전트가 p2/13 결과로 만들고, 사용자와 함께 범위를 정한다.

## 에이전트가 할 일

- [ ] 카테고리별 품종 후보 표 초안 (카테고리, 품목, 품종, 규격, 기준 단위, 출처와 코드, 대응 제철 품종 id)
- [ ] 각 품종에 **커버 상태** 표시
  - 충분: 매일 시세 (KAMIS, 축평원)
  - 부분: 격주·점포 한정 (참가격만)
  - 점포 데이터: 참가격 상품이 있어 점포·업태별 판매가가 나오는지 (배추·당근처럼 시세만 있는 품종 구분)
  - 없음: 어느 공공 출처에도 없음
- [ ] 한 품종에 출처가 여럿이면 우선순위 후보 (예: 삼겹살 KAMIS `500-4304-27` vs 축평원 `4304`/`27`)

## 정해진 것 (2026-10-19)

- **가격 품종 ID는 제철 패키지(`packages/seasonal`)의 품종 ID와 별도 체계로 둔다.** 두 체계는 매핑표로 잇는다 (pipeline.md 3-1 `variety_seasonal_map`). 목록 초안에 대응하는 제철 품종 id 열을 함께 둔다.
- 참가격 상품은 소분류 단위로 품종에 묶고, 맞지 않는 상품만 예외로 고친다 (`search-first-view` 결정 8).
- 식품만 다룬다. 참가격 생활용품은 제외한다.

## 함께 정할 것 (도메인 모델이 아직 정하지 않은 질문)

1. **가공식품의 품종 단위**: 글로서리에서 품종은 "사용자가 하나의 평소가를 기대하는 식재료"다. 라면은 "라면" 전체인가, "신라면 봉지"처럼 상품 수준인가? 참가격의 데이터는 상품 단위(604개)다.
   - 결과에 따라 GLOSSARY.md의 **품종**·**상품** 정의를 보강해야 한다 (`/domain-modeling`)
2. **MVP 범위**: 처음부터 가공식품을 포함할지, 신선식품(KAMIS + 축평원)만으로 시작할지
3. 기준 단위가 애매한 품종 (예: 라면은 1봉? 100g?)
