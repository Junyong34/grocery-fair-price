# 04. Supabase Free 일시정지 기준

Status: resolved
Type: research (AFK)
Blocked by: -

## Question

Supabase Free 프로젝트는 무엇을 "활동"으로 보고 언제 일시정지되는가? 매일 `ingest_writer`가 Supavisor로 붙어 쓰고 Storage에 올리는 것만으로 일시정지를 막는가? 일시정지되면 수집이 멈추고, 되살리는 방법(대시보드 수동 복구 등)과 그 사이 데이터가 어떻게 되는지도 확인한다. pipeline.md 6장 "확인해야 한다"의 답이다.

## 완료 기준

- 출처(Supabase 공식 문서·가격 페이지·공식 토론) 링크와 함께 답이 있고, heartbeat(14)나 알림(13)에 더할 것이 있으면 적혀 있다.

## Answer

2026-10-26. 조사 결과: [research/supabase-free-pause.md](../research/supabase-free-pause.md) (출처 링크·원문 인용).

- **기준은 "지난 1주 동안 충분한 사용자 DB 활동"이고 문턱값은 공개되지 않았다.** 공식 문서는 "대개 하루 몇 번의 DB 요청이면 충분하다"고만 하고, 어느 경로(Data API·Supavisor·Storage)를 세는지 적지 않는다.
- **매일 `ingest_writer`가 Supavisor 5432로 쓰는 것이 막아 줄 가능성은 높지만 확정할 수 없다.** 매일 외부 트랜잭션으로 2024-03 이후 정지되지 않았다는 사용자 보고가 있고, 풀러 연결은 세지 않는 것 같다는 직원 아닌 Collaborator의 추측도 있다. Storage 업로드가 세어지는지는 모른다.
- **정지 약 1주 전에 소유자에게 경고 메일이 오고**, 정지 뒤 한 통 더 온다 (공식). 경고 뒤 대시보드에서 열거나 요청을 보내면 막을 수 있다.
- **정지 중에는 모든 요청이 실패한다** (공식 HTTP 540, 커뮤니티 보고로는 DNS도 안 풀림). 데이터는 그대로이고 대시보드의 Resume으로 되살린다. 복구 기한은 문서 본문이 1년, 2024-06 공지는 90일이라 **90일을 마감으로 본다.** 무료 프로젝트 2개가 켜져 있으면 되살릴 수 없다.

반영할 곳:
- 13(실패 알림): 수집 중 HTTP 540, DB 주소 DNS 실패, Supavisor 접속 거부는 "Supabase 일시정지 의심"으로 분류해 키 오류처럼 즉시 알린다. DNS 실패는 러너 네트워크 문제와 구분이 어려워 2회 연속이면 확정으로 본다.
- 14(heartbeat): 이미 있는 비밀 키로 Storage를 한 번 조회해 정지 여부만 본다.
- 사람(01): 소유자 계정 메일함을 실제로 보는지 확인한다.
- 하지 않는 것: 매일 수집이 도므로 별도 keep-alive는 두지 않는다. 계정 전체 권한 토큰(Management API PAT)을 공개 저장소 Secrets에 넣지 않는다.
