# 05. 검토 도구 (읽기 전용 CLI)

Status: needs-triage
의존: 없음. 03이 이 도구를 쓴다.

## 결정

운영 어드민 화면은 만들지 않는다. 운영자 1명이 코드로 카탈로그를 고치므로, 필요한 것은 "무엇을 고칠지" 보여 주는 읽기 전용 보고서다. 인증·인가·CSRF·세션·역할·동시 편집 충돌 처리가 모두 필요 없다.

기존 `/admin`(개발 전용 인쇄물 관리)에 카탈로그 화면을 붙이지 않는다. 웹은 `web_reader`로 공개 판정만 읽고, pending 표(`source_code_map` 등)를 읽을 권한이 없다. 이 권한을 웹에 주지 않는다(ADR 0002).

## 명령

`packages/price-ingest/src/catalog/cli.ts`에 읽기 전용 하위 명령을 추가한다. 접속은 `INGEST_DATABASE_URL`(`ingest_writer`)이며 아무것도 쓰지 않는다. 읽기 전용 트랜잭션으로 연다.

### `catalog --pending [--source kamis|ekape|chamga] [--since 30]`

출처별 pending 목록. 정렬: 최근 관측일 내림차순.

| 열               | 뜻                                                              |
| ---------------- | --------------------------------------------------------------- |
| 출처·원천 코드   | KAMIS 품목·품종·등급 코드, 축평원 코드, 참가격 상품 ID          |
| 원문 이름·단위   | 원천 응답 그대로                                                |
| 최근 관측일      | 마지막으로 가격이 들어온 날                                     |
| 남은 관측값      | 지금 연결하면 다시 매핑될 행 수(보존 기간 안)                   |
| 비슷한 기존 품종 | 이름이 정확히 같거나 포함되는 품종·규격(참고용, 자동 연결 없음) |

출력은 터미널 표와 `--json` 두 가지. JSON은 에이전트에 "이 목록을 보고 `match.ts` 수정안을 만들어 줘"라고 넘길 때 쓴다.

### `catalog --report`

카탈로그와 운영 DB의 상태를 한 번에 보는 요약.

- 출처별 pending·ignored·mapped 수
- 매핑됐지만 단위 환산에 실패한 원천(가격이 `null`로 남는 행)
- 최근 판정 묶음에서 빠진 활성 규격(판정 행 없음)과 마지막 가격 날짜
- 제철 매핑이 있지만 판정 행이 없어 링크가 생기지 않는 품종(04)
- 운영자가 코드와 다르게 정한 매핑(`applyMappings`가 알리는 항목)

## 쓰는 법

- 주 1회 또는 새 출처·품목 변화가 의심될 때 `--report`를 본다.
- pending이 있으면 `--pending --since 30`으로 최근 것부터 03 흐름으로 처리한다.
- 알림(메일·이슈 자동 생성)은 만들지 않는다. 필요해지면 기존 수집 워크플로의 경보(`alert/`)에 "최근 7일 새 pending N건" 한 줄을 추가하는 정도로 한다.

## 하지 않는 것

웹 어드민 화면, 쓰기 기능, 일괄 편집기, 자동 연결.

## 완료 기준

- 두 명령이 운영 DB에서 읽기 전용으로 동작하고, 쓰기를 시도하면 실패한다(읽기 전용 트랜잭션 테스트).
- 출력 모양을 고정하는 vitest(작은 시드 데이터로 표·JSON 확인)를 먼저 작성한다.
- 03의 pending 재조회를 이 명령으로 한다.
