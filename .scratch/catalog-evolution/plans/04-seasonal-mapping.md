# 04. 제철 품종과 시세 연결

Status: needs-triage
의존: 01의 규격 URL. 02 변경 절차.

## 문제

제철 매핑(`varieties.ts`의 `seasonal` → `price.variety_seasonal_map`)은 다대다를 지원한다. 그런데 웹 `priceVarietyPath()`(`features/price/data/price-source.ts`)는 제철 ID와 같은 문자열의 시세 품종이 판정 목록에 있는지만 본다. 그래서 ‘마늘 → 깐마늘(국산)’, ‘참깨 → 국산·중국산’처럼 ID가 다른 연결은 링크가 생기지 않는다.

## 동작

- 제철 품종 하나에 시세 품종 여러 개가 연결될 수 있다. 연결 단위는 품종이고, 규격 단위 연결은 만들지 않는다. 품종 아래 규격은 01의 규격 목록이 보여 준다.
- 링크 대상은 현재 판정 묶음에 있는 품종만이다. 매핑이 있어도 판정 행이 없으면 링크하지 않는다.
- 대상이 하나면 그 품종 주소로 바로 간다. 여럿이면 제철 상세에 대상 목록(이름 + 짧은 구분, 예: ‘깐마늘 국산’)을 보여 준다. 임의의 한 대상 가격으로 대표하지 않는다.
- 시세 조회가 실패하면 링크만 빼고 제철 콘텐츠는 정상 표시한다(지금 `priceVarietyPath`의 catch 동작 유지).

## 바꿀 곳

1. 판정 payload 또는 검색 색인에 제철 ID 목록을 싣는다(06: 화면용 카탈로그 정보는 판정 묶음에 함께 싣는다). 그러면 제철 링크도 공개 판정과 같은 버전을 본다.
2. `priceVarietyPath(id)` → 연결 대상 배열을 돌려주는 함수로 바꾼다. `getPriceSource()`를 통해서만 읽는다.
3. 호출 경로 두 곳(제철 상세 전체 페이지, `@sheet/(.)foods/[food]` 가로채기 시트)을 함께 바꾼다.
4. 한 대상 / 여러 대상 / 없음 / 조회 실패 네 상태를 화면에서 구별한다.

## 누락 점검: 정기 작업 대신 테스트

제철 품종(`packages/seasonal`의 `foods.generated.ts`)과 시세 카탈로그(`varieties.ts`)가 모두 코드에 있다. 그래서 정기 점검 작업 대신 vitest 테스트로 검사한다.

- 시세 카탈로그가 가리키는 제철 ID가 모두 제철 데이터에 존재한다(실패).
- 숨긴 품종이 제철 매핑에 남아 있지 않다(실패).
- 시세 품종과 이름이 정확히 같은 제철 품종인데 매핑이 없는 경우를 목록으로 출력한다(경고만, 실패 아님). 연결 판단은 운영자가 한다.

테스트 위치는 의존 방향을 보고 정한다(`price-ingest`가 `@workspace/seasonal` 데이터를 읽는 것이 가능한지 구현 전에 확인).

"판정 행이 없어 링크가 사라진 매핑"은 운영 DB 상태라 테스트로 못 본다. 05의 `catalog --report`에 한 줄로 넣는다.

## 하지 않는 것

정기 매핑 점검 작업, 후보 자동 추천·자동 확정, 이미지 유사도·AI 분류.

## 완료 기준

- 마늘·참깨처럼 ID가 다른 연결과, 꽃게의 여러 시세 품종 연결이 제철 상세·시트 두 곳에서 동작한다.
- 판정 행이 없는 대상은 링크되지 않는다.
- 시세 조회 실패 시 제철 상세·시트 콘텐츠는 정상 표시된다.
- 누락 검사 테스트가 `pnpm test`에 포함된다.
- 375·1280에서 한 대상·여러 대상·없음 상태 확인.
