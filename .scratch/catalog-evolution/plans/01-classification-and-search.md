# 01. 품종 × 규격 판정과 검색

Status: needs-triage
의존: 없음. 기존 판정 묶음 포인터로 공개한다(06). 다른 계획을 기다리지 않는다.

## 문제

판정·검색·상세가 품종마다 기본 규격 하나만 다룬다. 냉동 꽃게, 시금치 중품처럼 이미 수집·집계되는 규격의 가격을 화면에서 볼 수 없다. 규모는 품종 136, 규격 200, 다규격 품종 43, 최대 6규격(2026-11-05)이다.

근거: `judgment/cli.ts` 57·66·80행의 `s.is_default` 조인, 75행 평소가의 `variety_id` 단독 키, 웹 `queries/get-variety.ts`의 `limit 1`.

## 동작

- 카테고리 → 품목 → 품종 → 규격 관계는 그대로 둔다. 규격을 품종으로 승격하지 않는다.
- 판정 단위는 공개된 품종 × 규격이다. 판정 묶음 한 벌에 규격마다 한 행.
- 검색 결과는 품종 묶음 아래 규격 행이다. 검색어가 규격 이름·별칭과 맞으면(‘냉동 꽃게’) 그 규격을 맨 위에 둔다. 다른 규격 가격으로 대신하지 않는다.
- 규격 속성(보관 상태·크기·등급·성별)은 1차에 규격 이름 검색으로만 다룬다. 속성별 필터·구조화 저장은 하지 않는다.
- 평소가가 부족하면 ‘판정 전’, 최근 가격이 없으면 마지막 날짜와 오래됨을 표시한다. 판정 행이 없는 규격은 검색에 넣지 않는다.

예시: `꽃게 / 냉동`, `꽃게 / 암꽃게 냉장`, `꽃게 / 수꽃게 냉장`. 냉동 암·수꽃게는 03에서 원천을 연결한 뒤에만 생긴다. 성별을 모르는 코드는 추측해 붙이지 않는다.

검색 화면 예시(시금치, 중품 연결 후):

```
검색: 시금치
┌──────────────────────────────┐
│ 시금치                        │
│   상품   100g 1,280원  보통   │ → /prices/spinach
│   중품   100g   980원  판정 전│ → /prices/spinach/mid
└──────────────────────────────┘
```

## 상세 화면: 규격마다 한 페이지 (2026-11-05 결정)

상세는 규격 하나만 보여 준다. 한 페이지에 여러 규격의 판정을 함께 싣는 안(판정 카드 여러 장, 추이 두 선)은 기각했다. 판정·담기·공유 링크가 모두 규격 단위라 페이지도 규격 단위로 맞춘다. 꽃게처럼 규격이 5~6개인 품종에서도 페이지 길이가 변하지 않는다.

- **규격 탭:** 상세 상단에 그 품종의 공개 규격을 탭으로 보여 준다(`상품 / 중품`). 탭마다 다른 주소이고, 누르면 그 규격 페이지로 이동한다(링크 탭, 상태 전환 아님). 규격이 하나뿐인 품종은 탭을 그리지 않는다.
- **탭 순서:** 카탈로그의 `specs` 순서(기본 규격이 첫째).
- **탭에 없는 규격:** 판정 행이 없는 규격은 탭에 넣지 않는다. 그 규격 주소로 직접 들어오면 "지금은 시세를 제공하지 않습니다" 안내를 보여 준다(404 아님).
- **다른 규격 가격:** 판정 카드 아래에 같은 품종의 다른 규격을 한 줄씩 작게 보여 준다(규격 이름 · 오늘 가격 · 판정 배지 → 그 규격 페이지 링크). 상품·중품 차이를 확인하려고 탭을 오가지 않아도 되게 한다. 추이 그래프·평소가는 현재 규격 것만 그린다.
- **판정 전 표시:** 새로 연결한 규격(예: 중품)은 평소가가 쌓일 때까지 판정 배지 대신 ‘판정 전’과 집계 시작일을 보여 준다.
- **담기:** 지금 보고 있는 규격을 담는다. 담기 목록 항목은 규격 이름을 함께 표시한다(`시금치 · 중품`).
- **컴포넌트:** 탭은 기존 `link-tabs`(`packages/ui`)를 먼저 검토한다. 화면 명세(`.scratch/price-screens/spec.md`)의 상세 절에 탭과 "다른 규격 가격" 영역을 추가한다.

## URL

- `/prices/[variety]`: 기본 규격을 보여 준다. 기존 주소는 그대로 동작한다. 기본 규격 slug(예: `default`)는 URL에 드러나지 않는다.
- `/prices/[variety]/[spec]`: 그 외 규격. 기본 규격 slug로 들어오면 품종 주소로 보낸다.
- 쿼리(`?spec=`)를 쓰지 않는 이유: Cache Components에서 `searchParams`를 읽으면 그 페이지가 요청마다 렌더링된다. 경로 세그먼트는 `generateStaticParams`로 미리 만들 수 있다. 구현 전에 `apps/web/node_modules/next/dist/docs/`와 `apps/web/docs/nextjs-16-patterns.md`로 확인한다.
- 경로는 `routes.price`에 추가하고 `shared/seo/pages.ts`에 등록한다. 규격 페이지는 색인 대상이고, 사이트맵·OG·canonical을 정한다.

## 바꿀 곳

1. `judgment/cli.ts`: `is_default` 조인 3곳을 공개 규격 전체로 바꾼다. 평소가·추이 조회의 키를 `(variety_id, spec_id)`로 바꾼다. 키만 바꾸고 묶음 검사(행 수 하한 등)를 그대로 두면 검사가 틀어지므로 함께 고친다.
2. `judgment/build.ts`, `packages/price/src/schema.ts`: payload의 `id`(품종 slug) 의미는 유지하고 `spec`(slug·이름·기본 여부)을 추가한다. 웹이 한 행을 고르는 키는 `(id, spec)`이다.
3. 배포 순서(ADR 0004 보완): 웹이 `spec` 없는 옛 payload도 읽게 먼저 배포 → 배치 변경 → 웹이 규격 행을 쓰게 배포. 옛 payload에서 `spec`이 없으면 기본 규격으로 본다.
4. `queries/get-variety.ts`: `(품종, 규격)`으로 조회한다. 규격이 없으면 `spec.is_default` 행을 명시적으로 고른다.
5. 웹 소비자 전수 조사: `PriceSource`, 검색 매칭·정렬, 상세, 카탈로그(`/prices`), 메인, 담기, 최근 본, 추천 목록. 품종 id 하나로 Map을 만드는 곳은 규격 행이 서로 덮어쓴다.
6. 기기 저장: `price:basket`, `price:recent` 키는 그대로 둔다. 항목에 `spec`을 추가하고 없으면 기본 규격으로 읽는다. 담은 규격이 사라지면 항목을 지우지 않고 "시세 없음"으로 표시한다.

## 대안과 판단

- 규격마다 품종을 새로 만드는 안: ID·제철 연결·이력 이전 비용이 크다. 기각.
- 상세에서만 규격을 바꾸는 안: 검색으로 원하는 규격을 바로 찾는 문제가 남는다. 기각.
- 한 상세 페이지에 모든 규격 판정을 함께 싣는 안: 비교는 쉽지만 규격이 많은 품종에서 길어지고 판정·담기 단위가 흐려진다. 기각하고 "다른 규격 가격" 한 줄 목록으로 비교를 돕는다.
- 규격을 추가할 때는 02의 slug 규칙을 따른다. 예: 시금치는 기존 규격 slug `default`를 유지한 채 이름만 `상품`으로 바꾸고 `mid`(중품)를 덧붙인다.
- 분류 규칙 자체(원산지=품종, 보관·크기·등급=규격)는 꽃게·시금치·사과·수입산 육류 네 사례로 맞는지 확인만 하고 고치지 않는다.

## 완료 기준

- 꽃게 냉동·냉장, 시금치 상품·중품이 각각 다른 판정·추이·평소가를 갖고 가격이 섞이지 않는다(배치 테스트).
- ‘꽃게’, ‘암꽃게’, ‘냉동 꽃게’, 초성·별칭 검색이 의도한 행을 맨 위에 둔다(`packages/price` 검색 vitest를 먼저 작성).
- 규격 주소의 새로고침·공유·뒤로 가기·담기 후에도 선택 규격이 유지된다.
- ‘시금치’ 검색에 상품·중품 두 행이 나오고, 각 행이 해당 규격 페이지로 간다.
- 상세의 규격 탭이 공개 규격만 보여 주고, 규격이 하나인 품종에는 탭이 없다. "다른 규격 가격" 목록이 현재 규격을 빼고 나온다.
- 판정 행이 없는 규격 주소는 안내 화면을 보여 주고 404가 아니다.
- 기존 품종 주소와 규격 없는 기기 기록이 계속 열린다.
- 옛 payload + 새 웹, 새 payload + 옛 웹 두 조합에서 목록이 비지 않는다.
- 375·1280에서 검색·상세·담기 확인.
