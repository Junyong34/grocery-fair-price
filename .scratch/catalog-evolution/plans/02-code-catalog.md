## 결정

카탈로그 원본은 계속 코드다. 운영자가 1명이고 코드를 직접 고치므로, DB 원본 전환과 어드민 쓰기는 비용만 늘린다.

| 필요           | 코드 원본에서 해결하는 방법                                                        |
| -------------- | ---------------------------------------------------------------------------------- |
| 변경 기록·이유 | 커밋 메시지(`feat: …`, 한국어)                                                     |
| 변경 전후 비교 | `git diff`, `catalog --dry-run` 출력                                               |
| 되돌리기       | `git revert` → 다시 적용 → 판정 재실행                                             |
| 검토           | 커밋 전 dry-run 결과를 보고 판단                                                   |
| 백업           | 카탈로그 매핑은 코드로 다시 만들 수 있다. 코드 밖 운영 결정만 `pg_dump`로 보존(06) |

## 변경 절차 (표준 흐름)

1. `varieties.ts`·`match.ts` 수정.
2. `pnpm --filter @workspace/price-ingest test`로 카탈로그 정합성 테스트 통과.
3. 운영 DB에 `catalog --classes --dry-run`, `catalog --mappings --dry-run`. 숨겨질 품종·바뀔 매핑·다시 매핑될 관측값 수를 확인한다. 예상과 다르면 멈춘다.
4. 커밋 후 실제 적용: `--classes` → `--mappings` 순서. 관측값 재매핑과 일자 요약 재계산은 `--mappings`가 한다.
5. `usual` → `judgment` 실행(또는 다음 정기 배치를 기다림). 판정 묶음 검사를 통과하면 공개된다(06).

이 절차를 `packages/price-ingest`의 README나 `pipeline.md`에 한 번 적어 두고, 매번 같은 순서로 한다. 단계를 하나로 묶는 스크립트는 반복해서 불편할 때 만든다.

## 보강할 것

- **dry-run 출력 정리:** 지금 출력이 숨김·매핑 변경·재매핑 수를 한눈에 보여 주는지 확인하고, 부족하면 요약 줄을 추가한다. 숨겨질 품종이 있으면 눈에 띄게 경고한다(규격 이름을 지우다 품종을 숨기는 실수 방지).
- **DB 손편집 금지 명시:** 카탈로그 표를 SQL로 고쳐도 `--classes`가 되돌린다. `pipeline.md`의 카탈로그 절에 한 줄 적는다. 예외는 `applyMappings`가 이미 보존하는 "운영자가 다르게 정한 매핑"뿐이다.
- **slug 규칙: 품종이든 규격이든 한 번 정한 slug는 바꾸지 않는다. 바꾸고 싶으면 이름만 바꾼다.**
  - 이유: `catalog --classes`는 slug로 같은 품종·규격인지 판단한다. slug가 바뀌면 이름 변경이 아니라 새 품종·규격 생성으로 처리된다.
  - 품종 slug를 바꾸면: URL(`/prices/[variety]`)·공유 링크·담기 기록·검색 색인이 옛 주소를 가리킨다. 옛 품종은 `hidden`이 된다.
  - 규격 slug를 바꾸면: 원천 매핑이 새 규격으로 옮겨진다(03 "연결 변경"). 보존 기간(KAMIS 90일) 이전 기록은 옛 규격에 남고, 새 규격은 최근 기록만 가져 평소가·판정이 한동안 흔들린다.
  - 규격 추가 예: 시금치는 `one()`으로 정의돼 규격 slug가 `default`다. 중품을 더할 때 `grades()`로 바꾸면 기존 규격이 `top`으로 새로 생긴다. 대신 `default`를 유지한 채 이름만 `상품`으로 바꾸고 `mid`(중품)를 덧붙인다.
  - 확인: 적용 전 dry-run에서 새로 생기는 규격과 바뀌는 매핑이 추가한 것뿐인지 본다. 기존 매핑이 바뀐다고 나오면 멈춘다.
  - 예외: slug를 꼭 바꾸거나 품종을 합칠 일이 생기면, 그때 이전 slug → 새 slug 대응(리다이렉트, 기록 이전)을 별도 티켓으로 만든다. 1차 범위 밖.
- **`varieties.ts` 크기:** 27KB, 136 품종이다. 규격이 늘어 편집이 불편해지면 카테고리별 파일로 나눈다. 지금은 나누지 않는다.
