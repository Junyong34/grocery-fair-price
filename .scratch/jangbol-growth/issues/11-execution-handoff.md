## Question

남은 결정 없이 실행할 수 있는 명세인가? 선행 결정들을 반복 저장하지 않고 참조하며 실행 순서와 검증 계약을 spec.md로 인계한다.

- 원안 19개 각각을 채택/축소/보류/범위 밖으로 배치하고 이유와 결정 티켓을 연결한다. 일정은 오늘부터 향후 2개월이며 연말·2027년판 발행과 김장 시즌의 시한을 명시한다.
- 각 실행 항목에 근거(THINK)·의존 관계·실패 판정 기준·선행 지표·담당·예상 작업량 범위·검증 방법을 적는다. 외부 검토/권한 대기와 개발 작업량을 구분한다.
- 개발자 주당 가용 시간을 확인한 뒤 1주/2~3주/2개월 배치를 잡는다. 운영자 주 2시간 초과 주에는 무엇을 줄일지 정한다. 기존 티켓의 완료 여부를 확인해 중복 구현을 없앤다.
- 성공=검색 상위 노출처럼 통제할 수 없는 완료 조건을 피하고, 배포 검증과 후행 성과 관측을 분리한다.
- 구현 검증은 저장소 규칙대로 root typecheck/lint(0 errors)/test, 화면은 next-dev-loop 375/1280·콘솔/수화 오류 없음, 순수 함수는 테스트 먼저를 포함한다. 검증한 구현 티켓은 main에 한국어 feat 커밋, PR 없이 진행한다.
- 안개가 남으면 완료로 닫지 않고 구체화된 질문을 새 티켓으로 만든다. spec.md는 실행의 인계 문서이며 결정의 정본은 각 티켓 Answer다.

완료 산출물: 운영자가 합의한 spec.md, 남은 열린 결정 없음, 보류/범위 밖 항목과 재검토 조건. 이 세션에서 구현을 시작하지 않는다.
