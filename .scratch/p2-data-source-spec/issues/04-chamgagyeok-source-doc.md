- [ ] 과거 조회 범위(2026-06-12부터)와, 그 이전은 파일데이터 XLS로 채울 수 있는지 (data.go.kr 파일데이터 확인)
- [ ] 604개 상품 중 MVP 후보 품종과 연결 가능한 상품이 얼마나 되는지 대략 집계
- [ ] 페이지 나누기 없음에 따른 호출량 추정 (업체 630곳 × 전 상품 방식 vs 상품 604개 × 전 업체 방식)
- [ ] 호출 한도(2,000건/일)
- [ ] **조사 일정 실측 표** (2026-10-12 판매점 100으로 일부 확인함, 아래 「실측 기록」). 다른 업태로 확장해 확정한다.
- [ ] **상품·판매점 마스터 변경 감시**: 마스터는 오늘(2026-10-12) 1회만 받아서 변경 이력이 없다. 월 1회 받아 이전본과 diff하는 절차를 정의한다 (신규·삭제·이름/용량/분류 변경, `goodId` 재사용 여부). 첫 비교 전까지 `goodId` 재사용은 **미확인**으로 표시한다.
- [ ] **마스터 604개 중 표본 조사에서 한 번도 안 나온 72개** (신선식품 40, 가공식품 17, 생활용품 15)의 원인 확인: 전체 판매점(630회) 한 번 훑어 상품별 등장 빈도를 집계한다. 호출 수를 먼저 계산하고 한도(2,000/일) 안에서 한다.
- [ ] **누락 감지 기준**: 한 조사일의 관측 수가 평소 대비 얼마나 줄면 누락으로 볼지, 판매점 100의 2026-08-07 사례(258개 일시 누락)와 신세계백화점 광주점·롯데슈퍼 포항점의 2026-09-25 0건 사례를 근거로 정한다. 사라짐 확정 회수 N도 여기서 제안한다 (p4/01 입력).
- [ ] **수집 방식 비교**: 판매점 기준(630회/조사일) 대 상품 기준(대상 상품 수만큼)의 호출 수·누락 감지 용이성을 정리하고 추천한다. 저장 구조는 어느 쪽이든 같다 (p4/01).
- [ ] **조사일 감지**: 조사가 없는 날은 오류 없이 빈 응답이 오므로, 매주 금요일에 판매점 1곳으로 확인한 뒤 데이터가 있을 때만 전체 수집을 시작하는 방식의 타당성 (조사일이 불규칙함, 아래 기록)

## 실측 기록 (2026-10-12)

판매점 100(현대백화점 미아점)을 2026-06-05~10-09의 모든 금요일에 호출한 결과. 호출 약 30회.

| 조사일 | 상품 수 | 이전 대비 |
|---|---|---|
| 06-12 | 365 | 처음 |
| 06-26 | 367 | +2 |
| 07-10 | 367 | 변화 없음 |
| 07-24 | 369 | +2 |
| **08-07** | **111** | **−258 (가공식품 257, 생활용품 1)** |
| 08-28 | 369 | 258개 복귀 |
| 09-11, 09-25 | 369 | 변화 없음 |
| 그 외 금요일(06-05, 06-19, 07-03, 07-17, 07-31, 08-14, 08-21, 09-04, 09-18, 10-02, 10-09) | 0 | 조사 없음 |

- 조사 간격: 2주, 2주, 2주, 2주, **3주**(08-07→08-28), 2주, 2주. 이 흐름이면 다음은 10-09인데 비어 있다 (한글날로 추정, 미확인). **격주 가정이 항상 맞지는 않는다.**
- 08-07의 258개 일시 누락은 삭제가 아닌 입력 누락으로 **추정**한다 (상품 구성만 근거).
- 가격 응답의 상품 ID는 확인한 532개 모두 상품 마스터에 있었다 (마스터에 없는 ID 0).
- 업태별 상품 수 (2026-09-25): 이마트 3곳 324~329, 현대백화점 2곳 350~363, 롯데슈퍼 부산연산점 289, GS더프레시 목동7점 190, 편의점 3곳 125~202. **판매점마다 취급 상품이 다르다.**
- 2026-09-25에 0건: 신세계백화점 광주점, 롯데슈퍼 포항점 (이유 미확인).
