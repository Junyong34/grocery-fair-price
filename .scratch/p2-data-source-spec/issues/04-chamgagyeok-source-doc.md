## Answer

산출물: [`grocery-price/docs/30-data/sources/chamgagyeok.md`](../../../grocery-price/docs/30-data/sources/chamgagyeok.md) (2026-10-19, 실호출 58회. 응답은 저장소 밖에 두고 수치만 문서에 옮겼다)

완료 기준 대조:
- 응답 필드: 4개 기능의 모든 필드를 도메인 개념에 연결하거나 "미사용"으로 표시했다 (3장). 제조사 코드는 "미결"(13장, p2/06).
- 조사 주기 검증: 표로 있다 (5-1). 점포 3~5곳 대신 `goodId=1000`을 금요일마다 불러 **4개 업태 446곳을 한꺼번에** 확인했다. 모든 업태가 같은 조사일을 쓴다.
- 마스터 변경 감시 절차(10장), `goodId` 재사용 **미확인** 명시, 누락 감지 기준(9장, 사라짐 확정 N=3), 수집 방식 비교(8장, 상품 기준 추천)가 있다.
- 코드 체계: AL·UT·AR·BU 전체 응답은 01에서 `reference/public-data/samples/chamgagyeok/standard-*.xml`로 이미 저장되어 있어 그것을 기준으로 삼았다. 따로 표 파일을 만들지 않았다.

새로 알게 된 것 (기존 문서와 다르거나 기존 문서에 없는 것):
1. **`inputDttm`이 실제 등록 시각이다.** 10-09분은 10-15~16에 입력됐다. 등록은 조사일 2일 전~7일 뒤로 퍼진다. "등록 지연"의 원인이 이것이다.
2. **일반 신선식품(배추, 삼겹살, 애호박 …)은 9개 점포 표본에서만 조사한다.** 조사일당 1~9곳(배추·무·양파는 현대백화점 포함 17~22곳). 업태·지역별 집계가 안 된다. 브랜드 신선식품(계란, 콩나물, 닭백숙)은 140~330곳.
3. 표본에 안 나온 72개 중 신선 40개는 대부분 위 표본 점포가 10-12 표본에 없었기 때문이다 (40개 중 36개가 10-09에 나옴).
4. **점포가 새 ID로 재등록된다.** 광주·전남 통합(AR `021800000`)으로 15곳이 새 ID(2220~2235)를 받았고 옛 ID는 마스터에 남았다. 신세계백화점광주점 09-25 0건의 원인. 롯데슈퍼포항점은 원인 미확인.
5. 편의점 4곳은 모두 본사(서울)다. 지역 집계에서 뺀다.
6. `goodPrice`는 행사가가 반영된 가격이다 (GS더프레시 1,180 대 1,380). 할인 필드가 없으면 "모름"이다 (파일데이터 안내문도 "미집계로 공란").
7. `entpId` 최대값 `5499990000`은 int4를 넘는다.
8. 파일데이터 15083256(월간 CSV, 점포 이름·**제조사 이름** 포함)이 있다. p2/06과 06-12 이전 채우기의 후보.

남은 것 (이 티켓의 완료 기준 밖):
- 72개 중 가공식품 17개의 원인과 630곳 전수 훑기: 호출 예산 때문에 하지 않았다. 상품 기준 정기 수집 첫 회가 같은 답을 준다.
- 10-16이 조사일인지: 등록이 7일까지 늦을 수 있어 10-23 이후 재확인.
- `plusoneYn=Y` 사례, `goodId` 재사용 여부.

p2/06 입력: 13장 (469 = 일반 신선식품 29개와 정확히 일치, 일반 축산물 5개는 444·448·530. 파일데이터 15083256의 제조사 이름 열).
