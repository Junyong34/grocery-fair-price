# 13. 출처별 제공 품목 전수 목록

Status: ready-for-agent
Type: research
Blocked by: -

## 목적

각 API가 **어떤 품목·품종·상품의 데이터를 실제로 주는지** 빠짐없이 뽑는다. 02~04가 필드를 정리한다면 이 이슈는 "무엇에 대해" 데이터가 있는지를 정리한다. 품종 리스트업(`p3-variety-catalog/01`)의 입력이다.

산출물: `grocery-price/docs/30-data/sources/item-inventory.md` + 원본 목록을 `reference/public-data/samples/inventory/`에 CSV로.

## 할 일

- [ ] KAMIS: `code-table.txt`의 부류·품목·품종·등급·구분을 정리한다.
  - 코드표에 있어도 **실제로 소매 데이터가 오는지**는 별도다. 품목별로 최근 30일 호출해 데이터 유무를 확인한다 (호출 수 계산 먼저).
  - 부류별 품목 수, 품종 수, 데이터 있음/없음, 단위, 소매/중도매 구분별 제공 여부
- [ ] KAMIS 구분 03·07: 품목 전수에서 실제 데이터가 있는 품목이 있는지 확인한다 (03은 6개 품목 0건, 07은 배추만 확인됨).
- [ ] KAMIS **이력 시작일**: 품목별·구분별(01, 02)로 가장 오래된 조사일. 시작일을 빼고 `numOfRows=1`로 첫 페이지를 보면 알 수 있다(결과는 조사일 오름차순). 근거: 도매(02) 수집을 MVP 이후로 미루는 결정이 "나중에 백필 가능"을 전제로 한다 (spec.md). 소매(01) 이력의 깊이는 평년 계산(5년 백필, `ingest-foundation/04`)에 필요하다.
- [ ] 축평원: 축종 7개 × 부위 코드 × 등급/원산지 구분 조합 중 **실제 응답이 오는 조합** 표
  - 호출 수 = 조합 수라서 1,000건/일 한도 안에서 계획한다. `itemCd`를 빼면 축종 전체가 오는 점을 이용한다.
- [ ] 참가격: 604개 상품을 분류(AL) 대·중·소로 묶어 개수 집계, 상품명·용량·단위 목록
  - 상품별로 가격이 실제 오는지 (최근 조사일 기준)
  - 판매점 630곳의 업태·지역 분포
- [ ] KAMIS 시장 분류: 소매 시장 코드 전체를 실명 전통시장 / 익명 대형유통("X-유통") / 도매시장으로 나눈 표 (`code-table.txt` 시장 시트). 품목별로 두 유형이 모두 오는지
- [ ] 삼겹살 등 축산의 **업태별 추이** 출처: 축평원에는 업태가 없고 KAMIS 축산 소매는 축평원 값과 같다. 참가격 정육 상품(예: `돼지고기 삼겹살(100g)`)으로 업태별(대형마트·백화점·슈퍼) 추이가 나오는지 확인
- [ ] 출처 간 겹침: 같은 식재료를 둘 이상의 출처가 주는 경우 (예: 삼겹살은 KAMIS와 축평원 둘 다, 두부·라면은 참가격만?)
- [ ] 예상 밖 발견은 "공공 출처에 없는 것"으로 따로 표시한다 (예: 일반 공산품, 간편식)

## 완료 기준

- 출처별 품목 수 표가 있고, "코드표에만 있음"과 "실제 데이터 있음"이 구분되어 있다.
- 겹치는 품목 표가 있다.
- 호출 수와 한도 소진량이 문서에 적혀 있다.
