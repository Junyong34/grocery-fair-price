# P2. 데이터 소스 명세 — 작업 분해

로드맵 ① 수집 기반의 요청·응답 분석 부분이다(이전 번호 P2, 2026-10-19 로드맵 재편). 목표와 완료 기준은 [roadmap.md](../../grocery-price/docs/00-overview/roadmap.md)에 있다. 수집·적재 작업은 `.scratch/ingest-foundation/`에 있다.

## 목표

주 출처 3개(KAMIS, 참가격, 축평원)의 모든 응답 필드를 도메인 개념에 연결하거나 "미사용"으로 표시한다. 보조 출처(가격 이슈, 제철) 조사는 확장 단계 E4로 미뤘다 (08~10).

## 현재 상태

- 3개 API 실호출 완료. 요청·응답 명세는 `grocery-price/docs/10-research/api-spec.md`에 있다.
- 인증키는 루트 `.env`의 `DATA_GO_KR_SERVICE_KEY` 하나로 3개 API를 모두 호출할 수 있다.

## 결정된 것

### KAMIS 구분 코드: MVP는 01 소매만 수집한다 (2026-10-12)

| 구분 | MVP | 이유 |
|---|---|---|
| 01 소매 | **수집** | 소비자가 보는 가격. 판정의 기준 데이터 |
| 02 중도매 | 제외 (후순위) | 단위가 소매와 달라(배추: 1포기 대 10kg) 평소가에 섞을 수 없고, 도매 시세의 쓰임(상승·하락 예고)은 MVP 이후다 |
| 03 친환경 | 제외 | 배추 등 6개 품목 호출에서 데이터 0건. 폐지로 추정, `p2/13`에서 전수 확인 |
| 07 친환경(신규) | 제외 | 배추 서울 5곳뿐. 규격(유기농)은 후순위 |

- **도입 시점의 전제**: 02 이력은 나중에 백필할 수 있다. 시작일을 빼고 호출하면 1996년 배추 중도매 가격이 왔다(`samples/kamis/missing-date-from.json`). 단 **배추 하나로만 확인**했다. `p2/13`에서 품목별 이력 시작일을 확인하고, 도입 시 백필 가능 여부를 다시 확인한다.
- **스키마**: `se_cd`(구분)를 필드로 둔다. 나중에 도매를 추가해도 구조가 바뀌지 않게 한다.
- **기존 결정과의 관계**: 도메인 모델의 "도매 시세는 보조 정보와 상승·하락 예고 문구에 쓴다"(2026-10-08)는 유지하되 적용 시점을 MVP 이후로 미뤘다. `domain-model.md` 9장에 기록했다.
- **수집하지 않는 대신 하지 않는 것**: 02용 어댑터·정규화·계약 테스트 baseline. 원본만 저장하는 절충안은 택하지 않았다(쓰지 않는 데이터의 정합성 검증 비용 때문).

## 결정이 필요한 것

- **문서 위치**: 로드맵은 출처별 문서를 `docs/30-data/sources/`에 두라고 한다. 지금 `docs/10-research/api-spec.md`가 있다. 제안: 02~04가 이 내용을 출처별 문서로 옮기고, 11에서 `api-spec.md`를 삭제하거나 이동 안내만 남긴다. (10-research는 "결정 아님" 참고 자료 폴더이기 때문)
