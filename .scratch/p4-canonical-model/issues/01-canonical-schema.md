# 01. 통합 스키마 설계

Status: resolved
Type: task
Blocked by: p2-data-source-spec/02, 03, 04

## 목적

3개 출처의 가격 데이터를 같은 모양으로 담는 통합 스키마를 설계한다. 출처마다 다른 필드 구성을 일관되게 만드는 것이 핵심이다.

산출물: [pipeline.md](../../../grocery-price/docs/30-data/pipeline.md) 3장 갱신. Postgres DDL·RLS·마이그레이션은 `ingest-foundation/02`가 이 결과로 만든다 (저장소는 ADR 0002로 Supabase).

## 설계할 것

- [x] **가격 관측** (핵심 레코드): 한 번의 조사에서 나온 가격 한 건
  - 출처, 출처 원본 키(재수집 시 중복 판별), 조사일, 수집 시각
  - 품종·규격 (매핑 전이면 비어 있을 수 있음)
  - 판매가와 기준 단위 환산가, 환산에 쓴 규칙 버전
  - 판매처(업태)·점포 또는 시장(전통시장/대형유통 구분)·지역
  - 행사 여부·기간·1+1
  - 가격 단계: 소매/도매 (**소매 시세**, **도매 시세** 구분). **MVP는 소매만 수집**하지만 구분(`se_cd`에 해당)은 필드로 둔다. 도매를 나중에 추가해도 구조가 바뀌지 않아야 한다 (`p2-data-source-spec/spec.md` 결정). 도매는 소매와 기준 단위가 달라 환산 기준이 필요하다는 점을 설계 메모로 남긴다.
  - 집계 여부: 시세(집계)인지 판매가(개별 관측)인지
- [x] **상품(내부 ID)과 출처 키 매핑** — 상품 중심 검색을 위한 구조 (2026-10-12 논의)
  - **상품**: 우리가 발급하는 불투명 ID(순번·ULID 등)와 속성(이름, 분류, 용량·단위). 발급한 ID는 **재사용하지 않는다.** 삭제하지 않고 상태(조사 중 / 조사 안 됨)와 **최초 확인일·마지막 확인일**을 둔다.
  - **출처 키 매핑**: (출처, 출처 키, 유효 시작일, 유효 종료일) → 상품. 참가격 `goodId`는 여기에 연결한다. 한 출처 키가 시기별로 다른 상품을 가리킬 수 있어야 한다 (`goodId` 재사용 위험, 아래 p2/04 확인 항목).
  - **상품 속성 이력**: (상품, 유효 시작일) → 이름·용량·분류. 이름이 바뀌어도 과거 가격이 같은 상품으로 이어진다.
  - 가격 관측·요약·URL은 **내부 ID만 참조**한다. 출처 키를 URL에 노출하지 않는다 (형식은 로드맵 ③④).
  - 범위: 상품 ID는 **참가격(그리고 제보, 온라인몰)용**이다. KAMIS·축평원은 상품 ID가 없고 품종·규격 단위 시세를 주므로 상품이 아니라 품종·규격에 연결한다. 한 ID로 세 출처를 통합하는 구조가 아니다.
  - 상품 → 품종 연결은 별도 매핑이다. 가공식품의 품종 단위는 `p3-variety-catalog/01`이 정한다. 연결 전에는 품종이 비어 있을 수 있다.
  - 새 출처 키가 나타났을 때 "새 상품인가, 기존 상품의 이름·용량 변경인가"를 가르는 기준은 마스터 변경 사례를 본 뒤 정한다 (p2/04 확인 결과 입력).
- [x] **상품 가격 조회용 구조**: 가격 관측(조사일 × 상품 × 점포) 원본은 쌓기만 하고 덮어쓰지 않는다. 검색 화면은 **상품별 일자 요약**(조사일, 최저·중앙·최고, 관측 점포 수, 행사 제외 중앙값)을 읽는다. 요약은 관측에서 언제든 다시 계산할 수 있는 **파생 데이터**로 둔다. 점포는 가격의 부가정보다 (상품 화면에서 점포별 가격을 보조로 노출).
- [x] **상품 사라짐·추가 처리**
  - 사라진 상품은 지우지 않고 "조사 안 됨 · 마지막 조사일"로 표시하며 과거 가격 추이를 계속 보여준다. 새 상품은 최초 확인일을 넣고, 가격이 쌓이기 전에는 "가격을 모으는 중"으로 보인다.
  - **"사라짐" 판정은 보수적으로 한다.** 참가격 점포 100의 2026-08-07 조사에서 상품 258개가 한꺼번에 빠졌다가 3주 뒤 복귀했다 (삭제가 아닌 입력 누락으로 추정). 따라서 (a) 연속 N회 조사에서 관측되지 않아야 "조사 안 됨"으로 확정하고, (b) 한 조사일의 관측 수가 평소의 절반 이하로 줄면 누락 경고를 남기고 그날은 판정에서 제외한다. N은 p2/04 결과를 보고 정한다.
- [x] **원천 코드 매핑**: 출처의 (부류·품목·품종·등급) 또는 (축종·부위·등급) 또는 상품ID → 품종·규격
- [x] **판매처·점포 마스터** (참가격 점포 기반, 점포→판매처 매핑), 시장·지역 마스터 (KAMIS 시장 유형, 축평원)
- [x] **원본 보관(raw)** 레코드: Storage 경로, 수집 요청 정보, 수집 시각, 계약 테스트 baseline 버전 (원문은 Supabase Storage)
- [x] **갱신 지연·정정 처리**: KAMIS 익일 재수집으로 값이 바뀔 때 이력을 어떻게 남기는지
- [x] 필드마다 출처별 변환 규칙 요약 표 (세부는 03의 어댑터 테스트. `adapters.md`는 만들지 않는다, 2026-10-19)
- [x] 변환 불가 케이스 목록과 방침 (예: 축평원 `grdNm`이 등급인지 원산지인지 구분 불가, 참가격 상품이 품종에 안 맞음)
- [x] 제보 가격과 미래 출처(온라인몰)를 나중에 같은 레코드에 담을 수 있는지 확인 (둘 다 확장 단계, 구조만 막지 않으면 된다)

## 설계 시 참고한 실측 (2026-10-12, p2/04에 상세 기록)

- 참가격 가격 조회는 한 번에 점포 1곳의 전 상품(약 330~370개) 또는 상품 1개의 전 점포(약 420곳)를 준다. 점포 100 기준 6/12~9/25에 상품 4개 추가, 진짜 삭제는 확인되지 않았다.
- 가격 응답의 상품 ID는 확인한 532개 모두 상품 마스터(604개)에 있었다. 마스터 604개 중 72개는 표본 조사에서 한 번도 나타나지 않았다 (원인 미확인).
- 상품 마스터의 대분류는 신선식품 71, 가공식품 386, 생활용품 147이다. 생활용품은 식자재 판정과 무관해서 정규화 대상에서 제외한다.
- 규모 추정: 점포 630 × 점포당 약 330상품 × 연 약 26회 = 연 약 540만 관측 (식자재로 한정하면 더 적다).

## 일관성 기준

- 같은 의미의 필드는 출처와 관계없이 이름·타입·단위가 같다.
- 출처에 없는 값은 `null`로 두고, "0"이나 빈 문자열과 구분한다.
- 모든 용어는 GLOSSARY.md를 따른다 (출처, 판매처, 점포 등).
- 테이블·인덱스는 Postgres 기준으로 쓴다 (ADR 0002). Supabase 전용 기능에는 기대지 않는다.

## 완료 기준

- 위 항목이 문서에 있고, 실제 샘플 응답 한 건씩을 스키마에 넣어 본 예시 표가 3개 출처 모두에 있다.
- 변환 불가 케이스가 목록으로 정리되어 있다.

## Answer

2026-10-19. [pipeline.md 3장](../../../grocery-price/docs/30-data/pipeline.md#3-테이블-설계-논리-스키마)을 완성된 논리 스키마로 다시 썼다 (3-0 공통 규칙 ~ 3-12). DDL·RLS 정책·마이그레이션은 `ingest-foundation/02`가 만든다.

- **가격 관측** `observation`: 세 출처 한 표. PK `(source_item_id, obs_date, place_id)`. 원천 키는 등록부 `source_item`(KAMIS `se-ctgry-item-vrty-grd`, 축평원 `judgeKind-itemCd-grdNm`, 참가격 `goodId`)으로, 시장·점포·지역 평균은 관측 위치 `obs_place`로 뺐다. 원천 자연키 → 이 세 열의 대응표가 3-3에 있다. 가격 단계(`price_tier` 소매/도매), 집계 여부(`obs_kind` 시세 표본 / 집계된 시세 / 판매가), 행사 3-state(`boolean null` 두 열 + 기간), 기준 단위 가격과 `unit_rule_id`(환산 규칙 버전), `source_registered_at`·`first_seen_at`·`last_seen_at`을 둔다.
- **축평원 평년 행**은 관측값이 아니라 `reference_observation`(요청 기준일을 붙임) → 품종 단위 `reference_price`.
- **정정**: 값(가격·행사)이 바뀌면 `observation_revision`에 이전 값을 남기고 `revision + 1`. 등록 시각만 바뀐 KAMIS 재등록은 정정이 아니다. 보존 기간 밖 재등록은 다시 넣고 집계를 다시 계산한다.
- **상품**: `product`(불투명 integer ID, 재사용·삭제 안 함, 조사 중/조사 안 됨, 최초·마지막 확인일, 연속 결측 수) + `product_source_key`(기간) + `product_attr_history` + `product_variety_map`/`al_variety_rule`. 사라짐은 `calc_param chamga.disappear_streak = 3`, partial 조사일은 세지 않는다.
- **원천 코드 매핑** `source_code_map`(기간·상태·대표 여부 `role`), 코드표 `source_code_table` (출처, 종류, 코드). 가격 품종 ID는 제철 품종 ID와 별도, `variety_seasonal_map`으로 잇는다.
- **판매처·점포·시장·지역**: `seller`, `store`(점포 → 판매처, 편의점 본사 `national_only`, 재등록 사슬 `lineage_id` + `store_link`), `market`(`market_type` 6종), `region` + `region_code_map`(AR 옛/새 코드, KAMIS `sgg_cd`, 축평원 `regionPrc` 번호), `source_master_change`.
- **원본 보관** `raw_object`: Storage 경로, 요청(키 제외), 수집 시각, 계약 baseline·어댑터 버전, `pending_load` 등 적재 상태, 해시 중복.
- **집계·판정**: `daily_quote`, `product_daily_summary`(행사 제외 중앙값, 판매처 2단 평균), `usual_price`, 판정 스냅샷은 묶음(`judgment_batch`)을 다 만든 뒤 포인터(`judgment_current`)를 바꾸는 방식. 최소 표본 수 등 ② 값은 `calc_param` placeholder.
- **수집 상태**: `ingest_run`, `source_day`(상태 7종, 기준·실제 행 수, 최대 등록 시각, 안정 횟수, 닫은 시각), `source_day_part`(품목·판매처·점포·신선 표본 단위 누락), `backfill_task`.
- **용량**(3-9): 보존 권장(KAMIS 관측값 90일, 참가격 8 조사일, 축평원·집계 영구)이면 DB 1년차 약 280~320MB, 이후 연 40~50MB. KAMIS 5년 650만 행을 관측값으로 두면 약 1GB라 둘 수 없다. 원본은 1년차 약 250~330MB, 이후 연 130~200MB.
- **예시**(3-10): KAMIS 애호박 경동 1,830원, 축평원 삼겹살 2,985원(+평년 2,721원), 참가격 왕뚜껑 센텀시티점 1,500원을 각 표에 넣어 봤다.
- **변환 규칙 요약**(3-11)과 **변환 불가 26건**(3-12).
- **확장**(3-8): 온라인몰·제보 모두 check 값 추가만으로 들어간다.

열린 결정(추천만 적음, pipeline.md 7장): 축산 대표 출처(조합 단위 추천), 참가격 점포별 보관 회차(8회 추천), KAMIS 백필 보관, 지역 코드 체계, 시도 범위 집계, 원본 파일 단위·보존 기간, 파티셔닝, 마스터 ID 타입, 기간 겹침 제약, 새 `goodId` 판별 기준, 판매처 매핑 기간, 1+1 가격 뜻, 상품 화면 점포별 가격의 공개 경로.
