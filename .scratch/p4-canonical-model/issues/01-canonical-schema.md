# 01. 통합 스키마 설계

Status: ready-for-agent
Type: task
Blocked by: p2-data-source-spec/02, 03, 04

## 목적

3개 출처의 가격 데이터를 같은 모양으로 담는 통합 스키마(논리 수준)를 설계한다. 출처마다 다른 필드 구성을 일관되게 만드는 것이 핵심이다.

산출물: `grocery-price/docs/30-data/canonical-model.md`

## 설계할 것

- [ ] **가격 관측** (핵심 레코드): 한 번의 조사에서 나온 가격 한 건
  - 출처, 출처 원본 키(재수집 시 중복 판별), 조사일, 수집 시각
  - 품종·규격 (매핑 전이면 비어 있을 수 있음)
  - 판매가와 기준 단위 환산가, 환산에 쓴 규칙 버전
  - 판매처(업태)·점포 또는 시장·지역
  - 행사 여부·기간·1+1
  - 가격 단계: 소매/도매 (**소매 시세**, **도매 시세** 구분). **MVP는 소매만 수집**하지만 구분(`se_cd`에 해당)은 필드로 둔다. 도매를 나중에 추가해도 구조가 바뀌지 않아야 한다 (`p2-data-source-spec/spec.md` 결정). 도매는 소매와 기준 단위가 달라 환산 기준이 필요하다는 점을 설계 메모로 남긴다.
  - 집계 여부: 시세(집계)인지 판매가(개별 관측)인지
- [ ] **상품(내부 ID)과 출처 키 매핑** — 상품 중심 검색을 위한 구조 (2026-10-12 논의)
  - **상품**: 우리가 발급하는 불투명 ID(순번·ULID 등)와 속성(이름, 분류, 용량·단위). 발급한 ID는 **재사용하지 않는다.** 삭제하지 않고 상태(조사 중 / 조사 안 됨)와 **최초 확인일·마지막 확인일**을 둔다.
  - **출처 키 매핑**: (출처, 출처 키, 유효 시작일, 유효 종료일) → 상품. 참가격 `goodId`는 여기에 연결한다. 한 출처 키가 시기별로 다른 상품을 가리킬 수 있어야 한다 (`goodId` 재사용 위험, 아래 p2/04 확인 항목).
  - **상품 속성 이력**: (상품, 유효 시작일) → 이름·용량·분류. 이름이 바뀌어도 과거 가격이 같은 상품으로 이어진다.
  - 가격 관측·요약·URL은 **내부 ID만 참조**한다. 출처 키를 URL에 노출하지 않는다 (형식은 P8·P9).
  - 범위: 상품 ID는 **참가격(그리고 제보, 온라인몰)용**이다. KAMIS·축평원은 상품 ID가 없고 품종·규격 단위 시세를 주므로 상품이 아니라 품종·규격에 연결한다. 한 ID로 세 출처를 통합하는 구조가 아니다.
  - 상품 → 품종 연결은 별도 매핑이다. 가공식품의 품종 단위는 `p3-variety-catalog/01`이 정한다. 연결 전에는 품종이 비어 있을 수 있다.
  - 새 출처 키가 나타났을 때 "새 상품인가, 기존 상품의 이름·용량 변경인가"를 가르는 기준은 마스터 변경 사례를 본 뒤 정한다 (p2/04 확인 결과 입력).
- [ ] **상품 가격 조회용 구조**: 가격 관측(조사일 × 상품 × 판매점) 원본은 쌓기만 하고 덮어쓰지 않는다. 검색 화면은 **상품별 일자 요약**(조사일, 최저·중앙·최고, 관측 판매점 수, 행사 제외 중앙값)을 읽는다. 요약은 관측에서 언제든 다시 계산할 수 있는 **파생 데이터**로 둔다. 판매점은 가격의 부가정보다 (상품 화면에서 판매점별 가격을 보조로 노출).
- [ ] **상품 사라짐·추가 처리**
  - 사라진 상품은 지우지 않고 "조사 안 됨 · 마지막 조사일"로 표시하며 과거 가격 추이를 계속 보여준다. 새 상품은 최초 확인일을 넣고, 가격이 쌓이기 전에는 "가격을 모으는 중"으로 보인다.
  - **"사라짐" 판정은 보수적으로 한다.** 참가격 판매점 100의 2026-08-07 조사에서 상품 258개가 한꺼번에 빠졌다가 3주 뒤 복귀했다 (삭제가 아닌 입력 누락으로 추정). 따라서 (a) 연속 N회 조사에서 관측되지 않아야 "조사 안 됨"으로 확정하고, (b) 한 조사일의 관측 수가 평소의 절반 이하로 줄면 누락 경고를 남기고 그날은 판정에서 제외한다. N은 p2/04 결과를 보고 정한다.
- [ ] **원천 코드 매핑**: 출처의 (부류·품목·품종·등급) 또는 (축종·부위·등급) 또는 상품ID → 품종·규격
- [ ] **판매처·점포 마스터** (참가격 판매점 기반), 시장·지역 마스터 (KAMIS, 축평원)
- [ ] **원본 보관(raw)** 레코드: 응답 원문, 수집 요청 정보, 수집 시각, 계약 테스트 baseline 버전
- [ ] **갱신 지연·정정 처리**: KAMIS 익일 재수집으로 값이 바뀔 때 이력을 어떻게 남기는지
- [ ] 필드마다 출처별 변환 규칙 요약 표 (상세는 `adapters.md`, 03에서)
- [ ] 변환 불가 케이스 목록과 방침 (예: 축평원 `grdNm`이 등급인지 원산지인지 구분 불가, 참가격 상품이 품종에 안 맞음)
- [ ] 제보 가격과 미래 출처(온라인몰)를 같은 레코드에 담을 수 있는지 확인 (`p3-variety-catalog/02` 결과 반영)

## 설계 시 참고한 실측 (2026-10-12, p2/04에 상세 기록)

- 참가격 가격 조회는 한 번에 판매점 1곳의 전 상품(약 330~370개) 또는 상품 1개의 전 판매점(약 420곳)을 준다. 판매점 100 기준 6/12~9/25에 상품 4개 추가, 진짜 삭제는 확인되지 않았다.
- 가격 응답의 상품 ID는 확인한 532개 모두 상품 마스터(604개)에 있었다. 마스터 604개 중 72개는 표본 조사에서 한 번도 나타나지 않았다 (원인 미확인).
- 상품 마스터의 대분류는 신선식품 71, 가공식품 386, 생활용품 147이다. 생활용품은 식자재 판정과 무관해서 정규화 대상에서 제외한다.
- 규모 추정: 판매점 630 × 매장당 약 330상품 × 연 약 26회 = 연 약 540만 관측 (식자재로 한정하면 더 적다).

## 일관성 기준

- 같은 의미의 필드는 출처와 관계없이 이름·타입·단위가 같다.
- 출처에 없는 값은 `null`로 두고, "0"이나 빈 문자열과 구분한다.
- 모든 용어는 GLOSSARY.md를 따른다 (출처, 판매처, 점포 등).
- 문서에 TypeScript 타입 초안을 포함해도 되지만, 저장소 종속 요소(테이블, 인덱스)는 넣지 않는다.

## 완료 기준

- 위 항목이 문서에 있고, 실제 샘플 응답 한 건씩을 스키마에 넣어 본 예시 표가 3개 출처 모두에 있다.
- 변환 불가 케이스가 목록으로 정리되어 있다.
