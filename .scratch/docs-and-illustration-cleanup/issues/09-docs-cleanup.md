## 목적

명세의 "문서 정리표"를 실행한다 (명세 결정 22~25).

## 할 일

- [ ] `.scratch/docs-audit/report.md` 이후(2026-11-10~) 바뀐 문서와, 그 보고서가 보지 않은 `prototypes/`·스킬·코드 주석·스크립트·데이터 속 경로를 대조해 정리표에 행을 더한다.
- [ ] 행마다 실행 전에 참조를 찾는다: Markdown 링크, 백틱 경로, 코드 주석, 스크립트 문자열, JSON·TS 데이터. 찾은 곳을 함께 고친다.
- [ ] 삭제는 세 조건(대체 문서 있음, 고유한 결정·출처 없음, 참조 정리 가능)을 모두 채울 때만 한다. 하나라도 아니면 유지하고 이유를 적는다.
- [ ] "확인 필요" 행(`apps/web/DESIGN.md` 분리, `grocery-price/README.md`·`roadmap.md` 현재 단계)은 사실을 확인해 조치를 정한다. 사용자의 판단이 필요하면 실행하지 않고 질문으로 남긴다.
- [ ] 완료 표시가 있는 명세의 미해결 티켓을 다시 확인해 상태를 맞춘다(`done` → `resolved` 등, 감사 2장).
- [ ] 정리표에 실행 결과 열을 더해 행마다 "함 / 안 함(이유)"을 적는다.

## 완료 기준

- 정리표의 모든 행에 결과가 있다.
- 옮기거나 지운 경로를 저장소 전체에서 찾아 남은 참조가 없다.
- `pnpm test` 통과(페이지 등록·경로 검사 포함).
