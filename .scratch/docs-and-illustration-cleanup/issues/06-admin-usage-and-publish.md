# 06. 그림 어드민: 용도 지정과 웹에 반영

Status: resolved
Type: task (prototypes/가 있는 기기에서)
Blocked by: 04 (resolved), 05 (resolved)

## 목적

사용자가 그림의 용도(제철, 이유식)를 정하고 웹에 반영한다 (명세 결정 15~17).

## 할 일

- [x] 제철로 지정: 새 품종을 만들거나 기존 품종에 그림을 연결한다. 품종 ID(새 품종일 때만), 표시명, 별칭, 카테고리, 제철 달, 대표 달, 근거 출처, 확인일을 받는다. 새 품종 ID는 기존 ID·옛 ID와 겹치면 막는다.
- [x] 근거 출처나 확인일이 비면 제철 미검증으로 저장하고, 제철달력에 나가지 않는다고 화면에 알린다.
- [x] 이유식으로 지정: 그림을 이유식 그림 목록(03의 JSON)에 연결한다. 궁합·월령 본문은 고치지 않는다.
- [x] 저장은 품종 원본과 이유식 그림 목록을 쓴다. 쓰는 JSON의 정렬과 들여쓰기를 고정해 diff가 바뀐 항목만 보이게 한다.
- [x] "웹에 반영" 버튼: 04의 생성과 검사를 돌리고, 실패하면 고칠 항목 목록을 화면에 보여 준다. 성공하면 바뀐 파일 목록을 보여 준다. 커밋은 하지 않는다.

## 완료 기준

- 새 그림을 검수 완료 + 제철(근거 있음)로 저장하고 반영하면 `/seasonal`에 나온다(375 · 1280).
- 같은 그림을 근거 없이 저장하면 제철달력에 없다.
- 이유식만 지정한 그림은 이유식 화면에만 나오고 품종 원본에 없다.

## Comments

2026-11-12: 마쳤다. `/admin/foods`의 그림 상세에 용도 지정이, 화면 위에 "웹에 반영"이 있다.

- 계산은 `features/admin-foods/lib/food-edit.ts`(`createFood`, `linkArt`, `setInfantArt`, `infantKeys`)이고 테스트가 있다. 파일 쓰기와 반영은 `server/use-actions.ts`.
- 제철: "새 품종"은 품종 ID(기본값은 그림 ID) · 표시명 · 별칭 · 카테고리 · 제철 달 · 대표 달 · 근거 출처 · 확인일을 받는다. 근거 출처와 확인일이 모두 있으면 `season: verified`·`basis: survey`, 하나라도 비면 `unverified`·`user`로 저장하고 폼이 저장 전에 어느 쪽인지 알린다. 이미 있는 ID, 옛 ID, 겹치는 표시명을 막는다. "기존 품종에 연결"은 품종의 `art`만 바꾼다.
- 이유식: 궁합표의 재료 이름이나 과일 도감의 과일 id · 주의 식재료 iconId에 그림을 연결하고, 연결된 항목은 "끊기"로 푼다. 이유식 데이터에 없는 항목은 받지 않는다.
- 품종 원본은 `formatFoodRegistry`로 써서 diff에 바뀐 품종만 보인다.
- "웹에 반영"은 `scripts/sync-foods.mjs --json`을 실행해 바뀐 파일, 고칠 항목, 알림을 보여 준다.

**1280 폭에서 시험용 그림(새우젓 `salted-shrimp`)으로 확인한 것** (끝난 뒤 품종 원본, `infant-art.json`, `art.json`, 웹 산출물을 모두 되돌렸고 해시가 01과 같다):

1. 검수 완료 → 제철 새 품종(근거 있음) 저장 → 웹에 반영 → `/seasonal/months/4`에 시험 품종이 나온다(375 · 1280). 그림은 품종 ID 폴더로 나갔다.
2. 같은 그림을 근거 없이 저장 → 반영 → `foods.generated.ts`와 웹 폴더에 없다.
3. 이유식 궁합 "새우"에만 연결 → 반영 → `/baby-food/pairings`에 그 그림이 나오고 품종 원본에는 없다.
4. 미검수로 되돌린 그림을 이유식이 가리키면 반영이 "미검수 그림이다(salted-shrimp)"로 멈추고 아무것도 바뀌지 않는다.

**알아 둘 것**

- 반영 직후 개발 서버에서 제철 화면을 열면 hydration 경고가 한 번 난다(월 선택 줄의 품종 수가 서버 54 · 클라이언트 53처럼 어긋남). 개발 서버가 캐시한 레이아웃이 반영 전 값이라 그렇고, 새로 고치거나 개발 서버를 다시 띄우면 없어진다. 화면 코드의 문제는 아니다.
- 이유식 궁합표의 재료 97개는 이미 모두 그림이 있다. 새 그림을 이유식에 쓰려면 기존 연결을 바꾸거나, 이유식 데이터에 재료를 먼저 더해야 한다.
- 이미 제철 미검증으로 있는 품종(31종)을 제철 검증으로 올리는 것은 07(기존 품종 편집)에서 한다. 06의 "새 품종"은 같은 ID를 막는다.
- 품종을 지우는 길은 없다(명세 결정). 잘못 만든 품종은 파일에서 지운다.
