# 08. GA4 연결과 이벤트

Status: ready-for-agent (사람 단계 A · B가 먼저)
Blocked by: 05(완료)

## 목적

인쇄물 내려받기 수(에디션별)와 A3 수요를 GA4로 본다. 시기별 입구 카드, A3 공개, 광고를 정할 근거다. 사이트 전체 페이지뷰도 같이 쌓인다. 호스팅이 정해지지 않아 Vercel Analytics가 아니라 GA4다(스펙 "측정").

## 먼저 읽을 것

- `apps/web/node_modules/next/dist/docs/01-app/02-guides/third-party-libraries.md` "Google Analytics" 절. 요점(Next 16.4 내장 문서, 2026-10-30 확인):
  - `@next/third-parties/google`의 `<GoogleAnalytics gaId />`를 루트 layout에 둔다. gtag.js는 하이드레이션 뒤에 불러온다. 옵션 `gaId`, `dataLayerName`, `debugMode`, `nonce`.
  - 이벤트는 클라이언트에서 `sendGAEvent('event', name, params)`. `<GoogleAnalytics />`가 위 layout에 있어야 동작한다.
  - 클라이언트 이동의 페이지뷰는 GA의 향상된 측정 "브라우저 기록 이벤트 기반 페이지 변경"이 켜져 있으면 자동이다. 직접 보내지 않는다(중복).
  - 패키지는 **실험(experimental)** 표시다. 설치할 판은 `next`(16.4.x)와 맞는 것으로 고정한다(`@latest` 그대로 두지 않는다).
- `apps/web/docs/seo.md` "환경 변수"(빌드 · 실행에 같은 값, `turbo.json` `build.env`)
- 이 폴더 `spec.md`, `issues/07-done-withdrawn-entry.md` Answer(A3 버튼 · `requestA3`가 처음일 때만 true)

## 사람 단계 (운영자)

### A. GA4 속성 (10분)

- [ ] https://analytics.google.com → 관리 → 속성 만들기. 시간대 **대한민국**, 통화 **KRW**.
- [ ] 데이터 스트림 → 웹. 주소는 쓸 예정인 도메인(정해지지 않았으면 임시 주소, 나중에 바꿀 수 있다). **향상된 측정**을 켜 두고, 그 안의 "브라우저 기록 이벤트 기반 페이지 변경"이 체크되어 있는지 본다.
- [ ] 측정 ID(`G-XXXXXXX`)를 루트 `.env`에 `GA_MEASUREMENT_ID`로 넣는다. 측정 ID는 페이지 HTML에 그대로 나가는 공개 값이라 비밀은 아니다.
- [ ] 관리 → 데이터 설정 → 데이터 수집: **Google 신호 데이터는 끈다**(광고 개인화용, 지금 필요 없다). 데이터 보존 기간은 기본(2개월)이나 14개월 중 고른다(이벤트 탐색 보고서를 길게 보려면 14개월).

### B. 맞춤 측정기준 등록 (5분, 코드 배포 전에 해 둔다)

이벤트 매개변수는 등록해야 보고서에 나온다. 등록 전 데이터는 소급되지 않는다.

- [ ] 관리 → 맞춤 정의 → 맞춤 측정기준 만들기(범위: 이벤트): `edition_id`, `edition_kind`, `paper`, `placement`.

## 에이전트 단계

### 1. 설계 결정(이 티켓에서 정한 것)

| 주제 | 결정 | 이유 |
|---|---|---|
| 불러오는 조건 | `process.env.GA_MEASUREMENT_ID`가 있고 운영 빌드일 때만 `<GoogleAnalytics>`를 그린다. 개발 서버에서 DebugView로 볼 때는 `GA_DEBUG=true`면 개발에서도 그리고 `debugMode`를 켠다 | 개발 중 클릭이 운영 데이터에 섞이지 않는다 |
| 환경 변수 | `GA_MEASUREMENT_ID`, `GA_DEBUG`. 서버 layout에서만 읽으므로 `NEXT_PUBLIC_` 접두가 필요 없다. `turbo.json` `build.env`에 더하고 `apps/web/docs/seo.md` 환경 변수 표에 적는다 | 정적 페이지가 빌드 때 값을 굳힌다 |
| 이벤트 보내는 곳 | `apps/web/shared/analytics.ts` 한 곳에 `track(event)` 함수. 이벤트 이름 · 매개변수를 판별 유니언 타입으로 고정한다. 화면 코드는 `sendGAEvent`를 직접 부르지 않는다 | 이름 오타가 타입 오류가 된다. 도구를 바꿔도 이 파일만 고친다 |
| 이벤트 이름 | GA4 규칙(영문 소문자 · 밑줄, 40자 이내). 아래 표 | |
| 개수 세는 기준 | 클라이언트 클릭 기준이다. 링크를 복사해 붙여 받거나 스크립트 차단기가 있으면 빠진다. 정확한 서버 집계(Route Handler에서 Measurement Protocol)는 하지 않는다. 필요해지면 따로 티켓 | 지금 목적(에디션 간 비교, 대략의 수요)에는 충분하다. MP는 API 비밀 키와 client_id 처리가 더 든다 |

이벤트:

| 이름 | 언제 | 매개변수 |
|---|---|---|
| `print_download` | 상세의 "PDF 내려받기" · 받은 뒤 "다시 내려받기"를 누를 때 | `edition_id`, `edition_kind`, `paper`("A4"), `placement`("sheet" \| "page") |
| `print_a3_request` | "A3도 원해요"를 처음 누를 때만(`requestA3()`가 true) | `edition_id`, `edition_kind` |
| `print_share` | 받은 뒤 "링크 복사" · "공유하기", 상세의 "공유" | `edition_id`, `method`("copy" \| "share") |
| `print_entry_click` | 2a · 2b 입구 카드를 누를 때 | `placement`("this-month" \| "month-timeline") |

`placement`(시트인지 페이지인지)는 `EditionDetail`에 prop으로 내려 준다(시트 라우트 · 페이지 라우트가 각각 넘긴다).

### 2. 작업 순서

- [ ] `pnpm --filter web add @next/third-parties@<next와 같은 16.4.x>` (설치 전 `npm view @next/third-parties versions`로 판 확인).
- [ ] `shared/analytics.ts`: `AnalyticsEvent` 유니언, `track(event)`(`"use client"` 모듈, `sendGAEvent` 호출. 창이 없거나 GA가 안 붙었으면 아무것도 안 한다). 순수 부분(이벤트 → `[name, params]` 변환)은 `analytics.test.ts`로 먼저 테스트.
- [ ] `shared/analytics-tag.tsx`(서버): 위 "불러오는 조건"대로 `<GoogleAnalytics gaId debugMode />` 또는 null. `app/layout.tsx`의 `</body>` 뒤에 둔다(문서 예시 위치).
- [ ] 호출 자리:
  - `features/seasonal/downloads/edition-actions.tsx`: 내려받기 링크 `onClick`(`setDone`와 같이), `A3Request`의 `requestA3(id)`가 true일 때, 링크 복사 · 공유하기.
  - `features/seasonal/components/share-button.tsx`: 상세의 글자 공유 버튼만 이벤트를 보내야 하므로 `onShared?(method)` 콜백을 더하거나 `EditionActions`에서 감싼다. 다른 화면(품종 · 월별)의 공유 버튼에는 이벤트를 붙이지 않는다(이 티켓 범위 밖).

- [ ] 문서: `apps/web/docs/seo.md` 57줄의 "GA4 등 분석 도구 …"(범위 밖 목록)와 `.scratch/seo/spec.md` 10 · 40줄의 "GA4는 넣지 않는다"를 고친다. `docs/project-structure.md`에 `shared/analytics*`와 환경 변수를 적는다. 로드맵 P9 줄에 "GA4: `.scratch/calendar-download` 08"을 덧붙인다.

### 3. 확인

- [ ] 콘솔 오류 · hydration 경고 없음(`next-dev-loop`).

## 사람이 정할 것 (작업 전에)

- [ ] **개인정보 처리방침**: GA4는 쿠키와 기기 식별자를 쓴다. 지금 사이트에 개인정보 처리방침 페이지가 없다. 국내 서비스는 GA 같은 도구로 행태 정보를 수집하면 처리방침에 적어 두는 것이 일반적이다(법률 자문이 아니다. 기준은 운영자가 확인한다). 선택지: (a) 이 티켓과 함께 짧은 `/privacy` 페이지(수집 항목 · 목적 · GA 사용 · 쿠키 거부 방법)를 만든다, (b) GA를 먼저 붙이고 FAQ · 문의 페이지 만들 때 같이 만든다. 추천은 (a). 정하면 따로 티켓으로 뺀다.
- [ ] 쿠키 동의 배너는 넣지 않는다(국내 이용자 대상, 지금 범위 밖). 해외 이용자를 받게 되면 다시 본다.
