# 08. GA4 연결과 이벤트

Status: resolved (코드). 남은 것: 사람 단계 A · B, 실제 측정 ID로 DebugView 확인
Blocked by: 05(완료). 운영 배포는 10(개인정보 처리방침)과 같이 나간다.

## 목적

인쇄물 내려받기 수(에디션별)와 A3 수요를 GA4로 본다. 시기별 입구 카드, A3 공개, 광고를 정할 근거다. 사이트 전체 페이지뷰도 같이 쌓인다. 호스팅이 정해지지 않아 Vercel Analytics가 아니라 GA4다(스펙 "측정").

## 먼저 읽을 것

- `apps/web/node_modules/next/dist/docs/01-app/02-guides/third-party-libraries.md` "Google Analytics" 절. 요점(Next 16.4 내장 문서, 2026-10-30 확인):
  - `@next/third-parties/google`의 `<GoogleAnalytics gaId />`를 루트 layout에 둔다. gtag.js는 하이드레이션 뒤에 불러온다. 옵션 `gaId`, `dataLayerName`, `debugMode`, `nonce`.
  - 이벤트는 클라이언트에서 `sendGAEvent('event', name, params)`. `<GoogleAnalytics />`가 위 layout에 있어야 동작한다.
  - 클라이언트 이동의 페이지뷰는 GA의 향상된 측정 "브라우저 기록 이벤트 기반 페이지 변경"이 켜져 있으면 자동이다. 직접 보내지 않는다(중복).
  - 패키지는 **실험(experimental)** 표시다. 설치할 판은 `next`(16.4.x)와 맞는 것으로 고정한다(`@latest` 그대로 두지 않는다).
- `apps/web/docs/seo.md` "환경 변수"(빌드 · 실행에 같은 값, `turbo.json` `build.env`)
- 이 폴더 `spec.md`, `issues/07-done-withdrawn-entry.md` Answer(A3 버튼 · `requestA3`가 처음일 때만 true)

이벤트:

| 이름 | 언제 | 매개변수 |
|---|---|---|
| `print_download` | 상세의 "PDF 내려받기" · 받은 뒤 "다시 내려받기"를 누를 때 | `edition_id`, `edition_kind`, `paper`("A4"), `placement`("sheet" \| "page") |

`placement`(시트인지 페이지인지)는 `EditionDetail`에 prop으로 내려 준다(시트 라우트 · 페이지 라우트가 각각 넘긴다).

### 폴더 구조 (`apps/web/shared/analytics/`)

여러 기능(제철, 나중에 가격)이 같이 쓰므로 `shared`에 둔다. 기능 폴더를 import하지 않는다.

```
shared/analytics/
  events.ts          이벤트 목록(카탈로그). 이벤트 이름 → 매개변수 타입, 이벤트마다 한 줄 설명(언제 보내는지).
                     GA에 맞춤 측정기준으로 등록한 매개변수 목록(REGISTERED_PARAMS)도 여기 둔다.
  events.test.ts     카탈로그 규칙 검사(아래)
  config.ts          켜짐 여부 · 측정 ID · 디버그를 환경 변수에서 읽는 곳(서버 전용, 한 곳)
  analytics-tag.tsx  서버 컴포넌트. config가 켜짐이면 <GoogleAnalytics>, 아니면 null. app/layout.tsx가 그린다
  track.ts           "use client". track(name, params) 하나. 카탈로그 타입으로 이름 · 매개변수를 검사하고 sendGAEvent로 보낸다.
                     GA가 안 붙었으면(개발 · 측정 ID 없음 · 차단기) 조용히 아무것도 안 한다
  tracked-link.tsx   "use client". 서버 컴포넌트의 링크에 클릭 이벤트를 붙이는 래퍼(<TrackedLink event={...}>)
```

`events.ts` 모양(예시):

```ts
/** 이벤트 카탈로그. 이벤트를 더하거나 지울 때는 이 표만 고친다. 지우면 부르는 곳이 타입 오류로 드러난다. */
export type AnalyticsEvents = {
  /** 인쇄물 상세의 "PDF 내려받기" · "다시 내려받기" */
  print_download: { edition_id: string; edition_kind: PrintKind; paper: PublishedPaper; placement: "sheet" | "page" }
  /** "A3도 원해요"를 처음 누를 때만 */
  print_a3_request: { edition_id: string; edition_kind: PrintKind }
  ...
}
export type AnalyticsEventName = keyof AnalyticsEvents

/** GA 관리 → 맞춤 정의에 등록한 매개변수. 새 매개변수를 쓰면 GA에도 등록하고 여기에 더한다. */
export const REGISTERED_PARAMS = ["edition_id", "edition_kind", "paper", "placement", "method"] as const
```

`track` 쪽 서명: `track<N extends AnalyticsEventName>(name: N, params: AnalyticsEvents[N]): void`.

`events.test.ts`가 지키는 규칙(카탈로그 값 표본 `EVENT_SAMPLES: { [N in AnalyticsEventName]: AnalyticsEvents[N] }`를 두고 검사한다. 표본이 모든 이벤트를 덮는 것은 타입이 강제한다):

- 이벤트 이름 · 매개변수 이름은 영문 소문자 · 숫자 · 밑줄, 영문자로 시작, 40자 이내, `google_` · `ga_` · `firebase_`로 시작하지 않는다(GA4 규칙).
- 이벤트당 매개변수 25개 이하, 문자열 값 100자 이하.
- 이벤트들이 쓰는 매개변수 집합 = `REGISTERED_PARAMS`. 새 매개변수를 쓰고 GA 등록을 잊으면 실패한다(메시지: "GA 관리 → 맞춤 정의에 등록하고 REGISTERED_PARAMS에 더한다").

이벤트 더하기 · 고치기 · 지우기 절차를 `shared/analytics/events.ts` 맨 위 주석 세 줄로 적는다(더하기: 카탈로그 + 표본 + 부르는 곳, 새 매개변수면 GA 등록. 지우기: 카탈로그에서 지우면 타입 오류가 부르는 곳을 알려 준다).

## Answer

2026-10-30 코드 완료. GA4 속성은 아직 없다(운영자 단계 A · B 남음).

- `apps/web/shared/analytics/`: `events.ts`(카탈로그 · `REGISTERED_PARAMS` · `EVENT_SAMPLES`), `events.test.ts`(GA4 이름 규칙 · 25개 · 100자 · 등록된 매개변수 = 쓰는 매개변수), `config.ts`(+ 테스트: ID 없으면 끔, 운영만, `GA_DEBUG`면 개발도), `analytics-tag.tsx`(루트 layout `</body>` 뒤), `track.ts`(`dataLayer`가 없으면 조용히 끝. `sendGAEvent`의 "초기화 안 됨" 경고를 피한다), `tracked-link.tsx`(제네릭 `eventName` · `eventParams`).
- `@next/third-parties@16.4.3`(next와 같은 판으로 고정). `turbo.json` `build.env`에 `GA_MEASUREMENT_ID`, `GA_DEBUG`.
- 이벤트 4개를 붙였다: 내려받기(`placement`는 시트 · 페이지 라우트가 `EditionDetail`로 넘김), A3 요청(`requestA3`가 처음일 때만), 공유(`ShareButton`에 `onShared`, `sharePage`는 shared · dismissed · unavailable로 바꿔 공유 창을 닫은 경우는 세지 않음), 입구 카드(`TrackedLink`).
- 확인: 측정 ID 없이 개발 서버 — GA 스크립트 없음, `dataLayer` 없음, 버튼 눌러도 콘솔 경고 없음. `GA_MEASUREMENT_ID=G-TEST1234 next build && next start`(3100) — HTML에 gtag 스크립트, 375에서 입구 카드 → 시트 → 내려받기 → 링크 복사 → A3를 누르니 `dataLayer`에 네 이벤트가 매개변수와 함께 쌓임(gtag.js 요청은 막아 실제 GA로는 안 보냄). `next build` 통과, 루트 lint · test 통과. 루트 typecheck는 다른 세션이 고치는 중인 `packages/seasonal/src/layout/scatter.ts` 한 줄만 실패한다(이 티켓과 무관, `apps/web` tsc는 통과).
- 남은 확인: 속성을 만든 뒤 `GA_DEBUG=true`로 개발 서버를 띄워 DebugView에서 이벤트 · 매개변수 · 페이지뷰 중복 없음을 본다.
