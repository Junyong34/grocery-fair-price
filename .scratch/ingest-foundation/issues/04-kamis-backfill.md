# 04. KAMIS 3년 백필과 계절비율 계산 입력

Status: ready-for-agent
Type: task
Blocked by: 03

## 목적

평소가의 계절비율([judgment.md](../../../grocery-price/docs/30-data/judgment.md) 1장)을 계산하려면 KAMIS 소매 3년 이력이 필요하다 (2026-10-27, 5년에서 3년으로 줄임). KAMIS 자체 API(cert_key)는 키가 없어 쓰지 않는다 (`p2/05` wontfix).

## 할 일

- [ ] 받을 범위: 구분 01 소매, MVP 품목 전체, 최근 3년. 기간 제한은 없고 호출 수 = ceil(행 수/1000): 축산 외 품목당 5년 60~100회, 소 437회이므로 3년은 그 약 60% ([kamis.md 8장](../../../grocery-price/docs/30-data/sources/kamis.md)). 동시에 여러 개 보내면 HTTP 504가 나므로 하나씩, 연 단위로 나눠 받는다
- [ ] 호출 수와 일일 한도(10,000) 계산, 며칠에 나눌지
- [ ] **적재 경로 (2026-10-20 결정, 2026-10-21 변경, pipeline.md 3-9 보관 1).** 관측값 표를 거치지 않는다. 고정 `UNLOGGED` 표는 쓰지 않는다 (RLS가 켜진 표에는 `ingest_writer`가 `COPY`할 수 없다, 3-0). 묶음(품목 × 연도)마다 한 세션·한 트랜잭션에서: 원본을 Storage에 올림 → `create temp table … on commit drop`에 `COPY` → 그 묶음 날짜로 `daily_quote`를 만듦 (정기 수집과 같은 집계 함수) → 최근 90일 행만 `observation`에 `insert … select` → `commit`하면 임시 표가 사라짐. 실제 `ingest_writer` 롤로 돌린다. 묶음 진행은 `backfill_task`. 한 품종이 여러 품목 코드에서 오면(참다래 `419` → 키위 `437`) 같은 묶음으로
- [ ] 용량 감시: 묶음 시작 전에 `pg_database_size`를 보고 400MB를 넘으면 멈추고 알린다. 무료 500MB를 넘으면 DB가 읽기 전용이 된다 ([database-size](https://supabase.com/docs/guides/platform/database-size)). 관측값에 넣었다 `delete`하는 방식은 지운 자리가 돌아오지 않아 쓰지 않는다
- [ ] 축평원 백필은 행이 적어(3년 약 3만) 관측값에 바로 넣는다
- [ ] **필수 시나리오: 보존 기간 밖 재등록** (pipeline.md 3-3). 백필한 날짜(90일 밖)의 행이 나중에 재등록되어 오면 관측값에 넣지 않고, 그 조사일의 원본 전체(백필 파일 포함)로 표본을 복원해 `daily_quote`를 바꾼다. 원본이 불완전하면(백필 원본은 1년 뒤 지운다, `purged_at`) 집계를 그대로 두고 기록·경보만. 그래서 백필 원본의 `raw_object.target_from`·`target_to`를 정확히 채운다
- [ ] 품목별 이력 시작일 확인 (`p2/13`과 공유)
- [x] 축평원 과거 조회 범위 실측 (축평원은 평년을 응답에 같이 준다): 하루 단위, 전국 2012-06 이전부터, 시도 값 2022-01부터. 5년 백필 12,782회, 하루 예산 800으로 약 16일 ([ekape.md 10·11장](../../../grocery-price/docs/30-data/sources/ekape.md))
- [ ] **화면 차트는 6개월까지만 쓴다 (2026-10-27 결정).** 탭은 1개월·3개월·6개월. 받은 과거 이력은 계절비율 계산에만 쓴다
- [ ] **`daily_quote` 보관 (2026-10-27 결정, 3-9 고칠 것).** 화면용은 최근 6개월. 6개월 밖은 계절비율을 해마다 다시 만들 재료로 무엇을 남길지 정한다. 후보: `national` 범위만 남김(연 약 12MB), 또는 지우고 해마다 KAMIS에서 다시 받아 평년을 다시 만듦. 다 지우면 다음 해 계절비율을 DB만으로 만들 수 없다
- [x] **평년 기간 (2026-10-27 결정).** 물가가 오르므로 몇 해 평균을 평소가로 쓰지 않는다. 3년 이력으로 계절비율(같은 시기 ÷ 그해 중앙값)만 만들고, 수준은 최근 26주 시세로 맞춘다 ([judgment.md](../../../grocery-price/docs/30-data/judgment.md))

## 완료 기준

- MVP 품목의 3년 소매 이력으로 계절비율이 계산되어 있고, `daily_quote`에는 최근 6개월(과 6개월 밖 보관 결정분)만, 관측값에는 최근 90일만 있다. 빠진 기간이 목록으로 있다.
- 백필이 끝난 뒤 DB 크기가 3-9 추정 안이다 (임시 표는 남지 않는다).
- 보존 기간 밖 재등록 테스트가 통과한다: 원본이 다 있으면 원본 전체 표본으로 집계가 바뀌고, 불완전하면 집계가 그대로다.
