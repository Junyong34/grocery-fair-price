# KAMIS 일별 도·소매 가격 (`perDay/price`)

한국농수산식품유통공사(aT) KAMIS의 일별 가격을 공공데이터포털(data.go.kr)판 API로 받는다. 이 출처가 주는 것은 **조사 시장 단위의 소매 시세 표본**(채소·과일·식량·특용·수산)과 **시도 평균 소매 시세**(축산)다. 로드맵 ① 수집 기반의 출처 문서이며 `p2-data-source-spec/02`의 산출물이다.

용어는 [GLOSSARY.md](../../../GLOSSARY.md)를 따른다. KAMIS의 원천 분류 이름(부류·품목·품종·등급)은 우리 용어와 뜻이 다를 수 있어서, 원천 쪽을 말할 때는 "원천 품목", "원천 품종"처럼 앞에 "원천"을 붙이고 API 필드명을 함께 적는다.

근거:
- 원본 명세 `reference/public-data/kamis/perDay-api-spec.txt`, 코드표 `reference/public-data/kamis/code-table.txt` (7개 시트)
- 저장 샘플 `reference/public-data/samples/kamis/` (2026-10-12 호출, `p2/01`). **아래 필드 표의 예시값은 모두 이 샘플에서 가져왔다.**
- 2026-10-19 추가 실측 42회 (이 문서의 미확인 항목을 풀려고 호출했다. 응답은 저장소에 두지 않았다). 본문에 **실측 10-19**로 표시한다.

## 1. 요청

`[`, `]`, `::`는 URL 인코딩한다 (`cond%5Bexmn_ymd%3A%3AGTE%5D`). curl은 `-g`를 주거나 인코딩해서 보낸다.

| 파라미터 | 명세 | 우리 규칙 | 설명 |
|---|---|---|---|
| `serviceKey` | 필수 | 필수 | 인증키. 로그·원본 파일·요청 기록에 남기지 않는다 (`<REDACTED>`) |
| `returnType` | 필수 (기본 JSON) | `JSON` 고정 | |
| `pageNo` | 필수 (기본 1) | 필수 | 1부터. 마지막 페이지를 넘기면 빈 `item[]`과 원래 `totalCount`가 온다 |
| `numOfRows` | 필수 (기본 10, 최대 1000) | `1000` 고정 | **실측 10-19: 1000보다 크게 주면 오류 없이 1000으로 줄인다** (`numOfRows=5000` → 응답 `numOfRows: 1000`) |
| `cond[exmn_ymd::GTE]` | 필수 | 필수 | 조사일 시작 `YYYYMMDD`. 빼면 1996년부터 온다 |
| `cond[exmn_ymd::LTE]` | 필수 | 필수 | 조사일 끝 `YYYYMMDD`. 빼면 0건 |
| `cond[ctgry_cd::EQ]` | 필수 | 필수 | 원천 부류 코드. 빼면 0건 |
| `cond[item_cd::EQ]` | 필수 | 필수 | 원천 품목 코드. 빼면 0건. **품목을 빼고 부류 전체를 받는 호출은 안 된다** |
| `cond[se_cd::EQ]` | 옵션 | **필수** | 구분 코드. 빼면 구분이 섞여 오고 구분마다 단위가 달라서 항상 `01`을 준다 |
| `cond[vrty_cd::EQ]`, `cond[grd_cd::EQ]`, `cond[sgg_cd::EQ]`, `cond[mrkt_cd::EQ]` | 옵션 | 쓰지 않음 | 품목 단위로 받아서 버리지 않고 모두 저장한다. 탐색용으로만 쓴다 |
| `selectable` | 옵션 | 쓰지 않음 | 받을 컬럼 지정. 원본은 모든 필드를 남겨야 해서 쓰지 않는다 |
| `cond[orgnl_reg_dt::GTE]` | **명세에 없음** | 보조로만 | **실측 10-19: 동작한다.** 등록일시가 주어진 시각 이후인 행만 온다 (`2026-10-01T00:00:00Z`와 `20261001` 둘 다 같은 결과). 재등록 감시에 쓸 수 있다 (6-3). 명세 밖이라 계약 테스트로 고정하고, 막히면 기간 재수집으로 되돌린다 |

**요청 쪽에서 검증한다.** 필수 조건을 빼거나 날짜 형식이 틀려도(`2026-10-01`) 오류 없이 `"0"`과 0건이 온다. 빈 결과를 "그날 데이터 없음"으로 읽기 전에, 요청이 위 필수 조건을 모두 채웠고 날짜가 `YYYYMMDD` 8자리인지 확인한다.

**정렬.** 결과는 **조사일 오름차순**이다. `numOfRows`로 자르면 오래된 날짜부터 온다. 최신 조사일을 보려면 기간을 좁히거나 `totalCount`로 마지막 페이지를 계산한다. 같은 조사일 안의 순서는 정해져 있지 않다고 본다. 5년치 2페이지(1,590행)를 이어 받았을 때 중복·누락은 없었다 (실측 10-19).

## 2. 응답

```
response.header: resultCode, resultMsg
response.body:   dataType, numOfRows, pageNo, totalCount, items.item[]
```

### 2-1. 봉투 필드

| 필드 | JSON 타입 | 예시 (샘플) | 도메인 연결 |
|---|---|---|---|
| `header.resultCode` | 문자열 | `"0"` | 미사용 (도메인). 오류 처리에만 쓴다 (9장) |
| `header.resultMsg` | 문자열 | `"정상"` | 미사용. 실패 시 로그에 남긴다 |
| `body.dataType` | 문자열 | `"JSON"` | 미사용 |
| `body.numOfRows` | **숫자** | `5` (`vegetable-baechu-retail.json`) | 미사용. 페이지 계산 |
| `body.pageNo` | **숫자** | `1` | 미사용. 페이지 계산 |
| `body.totalCount` | **숫자** | `381` (`vegetable-baechu-retail-14d.json`) | 미사용. 페이지 수 = `ceil(totalCount / 1000)`. 수집 상태의 기대 행 수 비교에 쓴다 |
| `body.items.item` | 배열 | 0건이면 `[]` | 미사용 (행을 담는 그릇) |

봉투의 페이지 필드는 JSON 숫자로 온다. 행(`item`) 필드는 모두 문자열이거나 `null`이다.

### 2-2. 행 필드 (`items.item[]`)

### 2-3. `exmn_dd_cnvs_prc`가 믿을 수 없는 이유

명세상 "kg 환산 가격"이지만 실제로는 경우마다 다르다.

| 경우 | 동작 | 예 |
|---|---|---|
| `unit`이 정확히 `kg` 또는 `g` (01, 07) | kg당으로 환산된다 | 쌀 `kg`·`20` 63,300원 → 3,165원 (실측 10-19). 감자 `g`·`100` → ×10. 참깨 `g`·`500` → ×2. 07 배추 `g`·`100` 880원 → 8,800원 |
| `unit`이 개수 단위 (`포기`, `개`, `손`, `마리`) | `exmn_dd_prc`와 같다 | 배추 `포기` 8,110 → 8,110, 사과 `개`·`10` 17,700 → 17,700 (샘플) |
| `unit`이 `kg(그물망 3포기)` 같은 묶음 (02) | 환산하지 않고 같은 값 | 중도매 배추 `10` 22,600 → 22,600 (`vegetable-baechu-wholesale.json`) |
| 축산 (부류 500) | **가격과 무관한 값**. 품목마다 모든 행이 같은 수 | 돼지 모든 부위·시도 `30320`, 계란·우유 `3032` (실측 10-19) |

`unit`이 `kg`·`g`일 때는 우리 환산 결과의 교차 검증용으로 쓸 수 있지만, 저장 규칙에는 넣지 않는다.

## 3. 코드 체계 (`code-table.txt`)

코드표는 원본 엑셀(`original-attachments.zip`)을 텍스트로 옮긴 것이다. **코드표가 실제 응답보다 오래되었다.** 코드표에 없는 코드가 실제로 온다 (아래). 그래서 처음 보는 코드는 버리지 않고 `source_code_map`에 `pending`으로 등록한다 ([pipeline.md](../pipeline.md) 3-1).

| 코드 | 시트 | 개수 | 형식 | 메모 |
|---|---|---|---|---|

## 5. 조사 시장과 시장 유형

전통시장 대 대형유통 추이의 근거다. 참가격에는 전통시장 점포가 없어서 신선식품의 전통시장 가격은 KAMIS로만 만든다 ([pipeline.md](../pipeline.md) 3-3).

### 5-1. 분류 규칙

시장 유형은 **`mrkt_nm`으로 가르고, 결과는 `mrkt_cd`에 붙여 저장한다.** 코드 모양으로는 가를 수 없다. 대형유통 코드가 대개 `0xx04xx`(예: `0110403`)이지만 `0360402`는 실명 전통시장 역전(순천)이고, `0321411`·`0372401`·`0312401`은 대형유통이다.

| 시장 유형 | `mrkt_nm` 규칙 (위에서부터 먼저 맞는 것) | 코드표 개수 | `01` 소매에 실제로 오나 |
|---|---|---|---|
| (시장 없음) 시도 평균 | `mrkt_cd`가 `null` | - | 축산 전부 |
| 대형유통 | `^[A-Z]+[0-9]*['`]?-유통$` (예: `C-유통`, ``B`-유통``, `M'-유통`, `BB1-유통`) | 88 | 예. 품목마다 30~34곳 (참깨 6곳) |
| 익명 업태 조사 시장 | `^[A-Z]+-(SSM\|백화점\|대형마트\|생협\|전문점\|직매장\|슈퍼마켓\|온라인)$`, `R-마트` | 58 | 아니오. `07` 친환경의 조사 시장이다 |

## 6. 갱신 주기·시각, 갱신 지연, 재수집

### 6-1. 등록 시각

`orgnl_reg_dt`를 KST로 바꿔 조사일과 비교했다 (배추 경동 소매 5년 1,590행, 실측 10-19).

| 조사일 대비 등록 | 행 | 비율 |
|---|---|---|
| 당일 22~23시 | 510 | 32% |
| 다음 날 (대부분 00~02시) | 820 | 52% |
| 2~3일 뒤 | 49 | 3% |
| 4~14일 뒤 | 103 | 6% |
| 15~60일 뒤 | 57 | 4% |
| 60일 넘게 뒤 (최대 249일) | 51 | 3% |

- 보통은 **D일 23시~D+1 02시(KST)** 에 등록된다. 06:30 수집이면 대개 D-1분이 있다.
- 최근에는 늦기도 했다: 10/12(월)분이 10/14 01:33, 10/13·10/14분이 10/16 23:35에 등록된 상태다 (10-19 조회 기준. 처음 등록이 늦었는지, 제때 등록 후 다시 등록되었는지는 이 값만으로 모른다).
- 축산은 `orgnl_reg_dt`가 `null`이라 등록 시각을 모른다. 10/19(월) 낮에 10/18(일)분이 이미 있었다.

### 6-2. 재등록과 정정

**`orgnl_reg_dt`는 마지막으로 다시 등록된 시각이다.** 첫 등록 시각은 남지 않는다.
- 10/12에 받은 샘플에서 10/06~10/08분의 등록일시는 각 조사일 밤이었다. 10/19에 다시 받으니 같은 행 141개(47 × 3일)가 모두 `2026-10-13T16:1x~16:3xZ`로 바뀌어 있었다. **가격은 하나도 바뀌지 않았다.**
- 몇 달 뒤 한꺼번에 다시 등록되는 일이 있다. 예: 2026-01-02~02-13분 30행이 2026-05-21 17시대(UTC)에 1~2분 간격으로 다시 등록되었다. 2025-05-20~06-25분도 2025-07-31~08-05에 다시 등록되었다.
- 그래서 **등록일시가 바뀌었다고 값이 바뀐 것은 아니다.** 정정 여부는 가격을 비교해서 정한다. 등록일시 변화는 "다시 받아 비교할 후보"를 고르는 신호로만 쓴다.
- 이전 문서의 "9/18분 등록이 9/30 (사후 등록)"도 늦게 처음 들어온 것인지 재등록인지 구분할 수 없다.

### 6-3. 재수집 규칙 (제안)

현재 설계([pipeline.md](../pipeline.md) 5-1)는 매일 D-1~D-3, 매주 최근 14일을 다시 받는다. 위 실측으로 보면 15일 넘게 지나 다시 등록되는 행이 7%라서 14일 재수집으로는 부족하다. 다음을 제안한다 (결정은 `ingest-foundation/05`).

1. **매일**: 품목마다 `exmn_ymd` D-3~D-1을 **한 번의 기간 호출**로 받는다 (축산 포함 최대 264 × 3 = 792행 < 1,000이라 1회). 날짜마다 따로 부르면 3배가 든다.
2. **매일, 재등록 감시**: 품목마다 `cond[orgnl_reg_dt::GTE]=<직전 실행 시각>` + `exmn_ymd` 최근 1년으로 부른다. 다시 등록된 행만 와서 대개 1회로 끝난다. 받은 행을 upsert하고 가격이 다르면 `revision++`. 축산은 `orgnl_reg_dt`가 `null`이라 잡히지 않으므로 1번의 범위를 넓히거나 축평원 쪽으로 정정을 잡는다.
3. **2가 막힐 때의 대안**: 매주 최근 14일, 매월 최근 120일 기간 재수집.

### 6-4. 갱신 지연 (같은 값이 이어짐)

기존 문서들(`domain-model.md`, `pipeline.md` 1장)은 "품절이면 전일가를 최대 5일 이어 쓴다"고 적었지만 **근거 문서를 찾지 못했다.** 실측으로는 5일 상한이 보이지 않는다. 경동 배추 5년치에서 같은 품종·등급의 같은 가격이 이어진 길이는 1일 288회, 2일 108회, 3일 58회, 4일 34회, 5일 14회, 6~14일 38회, 15일 이상 13회(최대 66 조사일)였다. 전통시장 가격은 실제로 몇 주 그대로일 수 있어서, 이어진 값이 품절에 의한 대체인지 실제로 같은 가격인지 응답만으로는 구분할 수 없다.

- 응답에는 "전일가 대체" 표시 필드가 없다.
- `carried_over` 표시(같은 값 3일 이상, [pipeline.md](../pipeline.md) 5-2)를 그대로 쓰면 전통시장 행의 상당수가 갱신 지연으로 잡힌다. 판정 설계(로드맵 ②)에서 기준 일수와 "평소가 계산에서 첫날만 센다" 규칙을 다시 정한다.

## 7. 휴일과 조사일

배추 경동 5년(2021-10-19~2026-10-16) 조사일 1,198일(연 약 240일)과 날짜별 전국 호출로 확인했다 (실측 10-19).

- **소매(축산 제외)는 평일만 조사한다.** 토요일은 5년 동안 2023-09-23 하루만 있었다 (전국 61행, 추석 연휴 전 토요일).
- **빈 평일**: 신정, 설·추석 연휴와 대체공휴일, 삼일절·어린이날·현충일·광복절·개천절·한글날·성탄절, 그리고 **근로자의 날**(2026-05-01 전국 0건), **선거일**(2026-06-03), **제헌절**(2026-07-17 전국 0건).
- **공휴일이 아닌데 전국 0건인 날**이 있다: 2025-12-05(금). 사유를 모른다. 공휴일 달력만으로 `empty_expected`를 정하면 이런 날이 `empty_unexpected`로 경고된다. 3일 다시 받은 뒤에도 0건이면 "조사 없음"으로 닫는 규칙이 필요하다.
- **축산은 매일 있다.** 주말·공휴일(10/9~10/12, 10/17·18)에도 72행씩 왔다 (돼지). 축평원의 매일 조사를 그대로 가져오는 것으로 보인다.
- `07` 친환경은 주 1회(화요일 조사일)다.

휴일 판정은 품목 하나가 아니라 **그날 소매 품목 전체가 0건인지**로 한다. 시장 하나나 품목 하나가 빠진 날은 휴일이 아니다 (5-3).

## 8. 과거 조회 범위와 5년 백필

**기간 제한이 없다 (실측 10-19).** 이전 문서의 "호출당 최대 1년"은 이 API에 맞지 않는다.
- 배추 소매 5년(20211019~20261019)을 한 요청으로 부르면 `totalCount` 62,562가 오고, 1년은 11,765다.
- 경동 배추 5년을 `numOfRows=1000`으로 2페이지(1,000 + 590행)에 받았다. 첫 행이 2021-10-19, 마지막이 2026-10-16이다.
- 페이지당 1,000행이 상한이라, 호출 수는 기간이 아니라 **행 수**로 정해진다.

## 10. 오류 처리 규칙

| 상황 | HTTP | 본문 | 처리 |
|---|---|---|---|
| 정상 | 200 | `response.header.resultCode: "0"`, `resultMsg: "정상"` | 성공. 0건도 성공으로 받되 1장 요청 검증과 7장 휴일 판정을 거친다 |
| 필수 조건 누락, 날짜 형식 오류, 미래 날짜 | 200 | `"0"` + `totalCount: 0` (`empty-missing-item.json`, `empty-future-dates.json`) | **오류로 오지 않는다.** 요청 생성 단계에서 막는다 |
| 마지막 페이지를 넘김 | 200 | `"0"` + 빈 `item[]`, `totalCount`는 그대로 | 페이지 수 계산 오류. 경고 |
| 명세에 없는 `cond[...]` 키 (예: `cond[foo::EQ]`) | 200 | `OpenAPI_ServiceResponse` JSON, `errMsg: HTTP_ERROR`, `returnReasonCode: "04"` (실측 10-19) | 요청 버그. 재시도하지 않고 알림 |
| 인증키 미등록 | **403** | `OpenAPI_ServiceResponse` JSON, `errMsg: SERVICE_KEY_IS_NOT_REGISTERED_ERROR`, `returnReasonCode: "30"` (`error-invalid-key.json`) | 재시도하지 않는다. 그 출처 수집을 멈추고 즉시 알림 |
| 없는 주소 | 400 | `OpenAPI_ServiceResponse` XML, `NO_OPENAPI_SERVICE_ERROR` (코드 12) | 설정 오류. 알림 |
| 한도 초과, 게이트웨이 오류, 시간 초과 | (미확인) | `OpenAPI_ServiceResponse` 계열로 추정 | 2s/4s/8s 재시도 후 `failed` ([pipeline.md](../pipeline.md) 5-2) |

판정 순서: HTTP 상태 → 본문 최상위 키가 `OpenAPI_ServiceResponse`인지 → `response.header.resultCode == "0"`인지. `OpenAPI_ServiceResponse`는 `returnType=JSON`이어도 JSON이 아닐 수 있으므로(400은 XML) 본문을 JSON으로 파싱하기 전에 형식을 확인한다.

행 단위 검증 (형식이 바뀌었는지):
- `exmn_ymd`가 8자리 숫자이고 요청 범위 안
- `se_cd`가 요청한 값과 같음
- `exmn_dd_prc`가 양의 정수 문자열
- `unit_sz`가 양의 정수 문자열
- `mrkt_cd`·`orgnl_reg_dt`의 `null`은 부류 500일 때만 정상

어긋난 행은 ② 관측값으로 넘기지 않고 ① 원본에만 남긴다.

## 11. 이 출처로 못 하는 것

- **평년·전년·전월 가격이 없다.** 응답은 그날 가격뿐이다. 평년은 이 API의 5년 이력으로 직접 계산한다 (`ingest-foundation/04`). 평년과 1년 전 값을 주는 KAMIS 자체 API(cert_key)는 키가 없어 쓰지 않는다 (`p2/05` wontfix).
- **판매처를 알 수 없다.** 대형유통은 `X-유통`으로 익명이고, 같은 글자가 같은 판매처인지 모른다. 판매처·업태별 비교는 참가격으로 한다.
- **점포 단위 판매가가 아니다.** 조사 시장 한 곳의 조사원 표본가다.
- **전일가 대체 여부를 알 수 없다** (6-4).
- **값이 바뀐 시각을 알 수 없다.** `orgnl_reg_dt`는 마지막 재등록 시각뿐이고 값이 바뀌지 않아도 바뀐다 (6-2).
- **축산의 시장별 값이 없다.** 시도 평균만 온다.
- **행사(할인, 1+1) 정보가 없다.**
- **부류 전체를 한 번에 받을 수 없다.** 품목마다 따로 불러야 한다.

## 13. 스키마 설계에 넘길 사실

- 응답 행 필드는 모두 문자열이거나 `null`이다. 저장할 때 형을 바꾼다: `exmn_ymd` → `date`, `exmn_dd_prc` → `integer`(원), `unit_sz` → `integer`(관측값 기준; 소수는 보지 못했지만 `numeric`이 안전), `orgnl_reg_dt` → `timestamptz`. 코드는 앞자리 0을 지키도록 `text`로 둔다 (`se_cd` `01`, `mrkt_cd` `0110212`).
- 원천 자연키 8개 (3장). 축산은 `mrkt_cd`가 `null`이므로 unique 제약에서 `NULLS NOT DISTINCT`나 빈 값 대체가 필요하다.
- `source_key`에 `se_cd`를 넣는다. 구분이 다르면 단위도 다르다 (예: `kamis:01-200-224-01-04`).
- 관측값의 unique 키에 **조사 시장**이 있어야 한다. 서울만 해도 같은 날 같은 원천 품종·등급에 시장 9곳이 온다.
- 시장 표: `mrkt_cd`(유일), 이름, `sgg_cd`, 시장 유형. 시장 유형 값은 `traditional`, `large_retail`, `wholesale`, `eco_channel`(07 익명 업태), `online`, `other`. 처음 보는 코드도 온다 (3장).
- 축산 행은 `scope`가 `sigungu`(시도) 또는 `national`(`sgg_cd` `1000`)이고 `market_id`가 없다.
- 하루 행 수는 품목당 18~264, 소매 전체는 하루 약 5,200행이다 ([pipeline.md](../pipeline.md) 1장).
- `orgnl_reg_dt`는 덮어쓰이는 값이다. 처음 받은 시각은 우리 쪽 `first_seen_at`으로 따로 남긴다.
