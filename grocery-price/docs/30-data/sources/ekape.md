# 출처: 축평원 "일자별 축산물소비자가격 정보"

축산물품질평가원(축평원) 축산물유통정보 서비스의 "일자별 축산물소비자가격 정보" 기능(`consumerPriceDaily`, API 이름 그대로)을 정리한 출처 문서다. 소고기·돼지고기·수입 소고기·수입 돼지고기·닭·계란·우유의 **소매 시세**와 **평년**을 준다. 로드맵 ① 수집 기반의 산출물이다 (`.scratch/p2-data-source-spec/issues/03-ekape-source-doc.md`).

- 근거: 원본 명세 `reference/public-data/ekape/openapi-guide.txt`(v2.9, 2023-08-31), 저장 샘플 `reference/public-data/samples/ekape/`(2026-10-12 호출), 2026-10-19 10:10~10:14 KST 추가 실호출 49회(축평원) + 3회(KAMIS 비교). 추가 호출의 응답은 저장소에 넣지 않았다.
- **실측**은 명세에 없거나 명세와 다르게 동작한 것이다.

| 항목 | 값 |
|---|---|
| 도메인 개념 | 소매 시세(전국), 평년 |
| 주소 | `http://data.ekape.or.kr/openapi-data/service/user/grade/consumerPriceDaily` (**http**. https 아님) |
| 형식 | XML만 |
| 인증 | 공공데이터포털 인증키 `DATA_GO_KR_SERVICE_KEY` (KAMIS·참가격과 같은 키) |
| 호출 한도 | 1,000건/일 (개발계정) |
| 조사 주기 | 매일 (2026년은 토·일·공휴일·명절에도 값이 있다) |
| 하루 양 | 당일 27행 + 평년 27행 = 54행, XML 약 41KB (gzip 약 6KB) |
| 과거 조회 | 2012-06까지 실측 확인. 2010-01은 0건 |

## 1. 요청

`GET http://data.ekape.or.kr/openapi-data/service/user/grade/consumerPriceDaily?serviceKey=…&standYmd=20261018&judgeKind=4304`

| 파라미터 | 명세 | 실측 | 설명 |
|---|---|---|---|
| `serviceKey` | 필수 | | 인증키. 64자 영숫자라 인코딩하지 않아도 된다 |
| `standYmd` | 필수 | 형식이 틀리면 `resultCode 99` (6장) | 기준일 `YYYYMMDD` |
| `judgeKind` | 필수 | | 축종코드 (2장) |
| `itemCd` | 필수 | **빼면 그 축종의 모든 품목코드가 온다** | 품목코드(부위) (2장) |

- 페이지 파라미터(`pageNo`, `numOfRows`)는 명세에 없고 응답에도 `totalCount`가 없다. 한 번에 축종 전체가 온다. 명세의 최대 메시지 크기는 50,000바이트인데, 가장 큰 소 응답이 약 15KB라 여유가 있다.
- **수집은 `itemCd` 없이 축종 단위로 부른다.** 하루 7회로 끝나고, 새 품목코드가 생겨도 놓치지 않는다 (아래 표처럼 실제 코드는 명세보다 많다).

## 3. 응답

```
response.header: resultCode, resultMsg      (정상: 00 / NORMAL SERVICE.)
response.body.items.item[]                   (0건이면 <items/>)
```

모든 값은 **문자열**이다. 값이 없는 지역 가격은 빈 태그가 아니라 **태그 자체가 빠진다** (예: 소 갈비 1등급은 17개 시도 중 13곳만 온다). 행 순서는 품목코드 순이 아니다 (소: 40, 50, 21, 22, 36). 정렬에 기대지 않는다.

| 필드 | 명세 이름 | 타입·빈 값 | 예시 (`pork-samgyeopsal.xml`) | 도메인 개념 |
|---|---|---|---|---|
| `resultCode` | 결과코드 | 문자열, 항상 | `00` | 수집 상태. `00`이 아니면 실패 (6장) |
| `resultMsg` | 결과메세지 | 문자열 | `NORMAL SERVICE.` | 미사용 (로그에도 그대로 남기지 않는다, 6장) |
| `standYmd` | 날짜구분(날짜/평년) | `YYYYMMDD` 또는 문자열 `평년` | `20261011`, `평년` | 날짜면 **시세의 조사일**, `평년`이면 **평년 행** 표시 (4장) |
| `judgeKind` | 축종코드 | 4자리 숫자 문자열 | `4304` | 원천 키의 일부 → 품목 (소고기, 돼지고기 …) 매핑 |
| `judgeKindNm` | 축종명 | 문자열 | `돼지` | 미사용 (코드로 충분. 운영자 화면 표시용으로만) |
| `itemCd` | 품목코드 | 2자리 숫자 문자열 (`01`처럼 앞 0 있음) | `27` | 원천 키의 일부 → **품종** 매핑 (예: 4304-27 → 국산 삼겹살) |
| `itemNm` | 품목명 | 문자열. 냉장·냉동, 크기·수량이 섞임 | `삼겹살`, `갈비(냉동)`, `XL30구` | 미사용 (매핑은 코드로. 냉장·냉동은 5장 규칙에서 참고) |
| `grdNm` | 구분명(등급/원산지) | 문자열 | `구분없음`, `1+등급`, `미국산` | 축종에 따라 **규격** 또는 **품종**의 원산지 (5장) |
| `ntslPrc` | 평균가격 | 정수 원 문자열 | `2985` | **소매 시세**(전국) 가격. `unit` 기준 |
| `maxPrc` | 최대가격 | 정수 원 | `3168` | 미사용. 실측: 17개 시도 `regionPrc` 중 최댓값과 같다 |
| `minPrc` | 최소가격 | 정수 원 | `2848` | 미사용. 실측: 17개 시도 중 최솟값과 같다 |
| `regionPrc1`~`17` | 시도별 가격 | 정수 원. 태그가 빠질 수 있음 | `3026` (서울) | **MVP 미사용** (7장) |
| `unit` | 단위 | 문자열 | `원/100g`, `원/Kg`, `원/30구`, `원/1L` | 원천 단위 → **기준 단위** 환산 규칙 (`source_code_map.unit_rule`) |

- `ntslPrc`는 시도 가격의 단순 평균이 아니다 (10-18 소 안심 1+등급: `ntslPrc` 17,707, 17개 시도 단순 평균 17,982). 표본 수 가중 평균으로 보인다. 전국 값은 직접 계산하지 말고 `ntslPrc`를 쓴다.
- 가격에 소수점이 온 적은 없다. 정수로 저장한다.

## 4. 같은 `itemCd`에 item이 여러 개 오는 이유

오류가 아니다. 한 품목코드의 행 수는 **`grdNm` 개수 × 2(당일 행, 평년 행)** 이다 (`p2/01` 확인).

| 예 | 행 |
|---|---|
| 돼지 삼겹살 (4304-27) | `20261011`/구분없음 2,985원, `평년`/구분없음 2,721원 → 2행 |
| 소 등심 (4301-22) | 1+등급·1등급 × (`20261011`, `평년`) → 4행 |

**평년 행에는 날짜가 없다.** `standYmd`가 `평년`이라서 어느 날의 평년인지는 요청의 `standYmd`로만 안다. 어댑터는 요청 기준일을 평년 행에 붙여서 `reference_price`에 넣는다 (`pipeline.md` 3-3).

**평년 행은 미리 나와 있다.** 당일 행이 아직 없는 기준일(오늘, 미래)이나 과거 데이터가 없는 날(2015-01-01, 2020-01-01)에도 평년 행은 온다. 그래서 "응답에 행이 있다"를 "그날 값이 들어왔다"로 읽으면 안 된다. **당일 행(`standYmd` = 요청 기준일)이 하나라도 있어야 수집 성공**이다.

### `평년`이 무엇의 평균인가 (미확정)

명세에는 정의가 없다. 삼겹살(4304-27, 전국)로 맞춰 봤다.

| 기준일 | 응답 `평년` | 같은 날 과거 값 | 단순 평균 | 최고·최저 뺀 3년 평균 |
|---|---|---|---|---|
| 2026-10-11 | 2,721 | 2021(10-12 대신) 2,668 · 2022 2,717 · 2023 2,722 · 2024 2,747 · 2025 2,855 | 2,742 | 2,729 |

- 어느 쪽과도 정확히 맞지 않는다. 같은 날 하루가 아니라 그 무렵 며칠의 평균을 쓰는 것으로 보인다.
- **시도별 평년은 지역 가격이 있는 해만 평균한다.** 2023-10-11의 시도별 평년은 2022-10-11 시도 값과 거의 같고(서울 2,847 대 2,848), 2022년 이전 평년에는 시도 값이 없다. 시도 값이 2022년부터 있기 때문이다 (9장). 반면 전국 평년은 그 전 해도 쓴다 (2023-10-11 전국 평년 2,338은 2022년 값 2,717보다 훨씬 낮다).
- 결론: **최근 몇 해(5년으로 보임) 같은 시기의 평균**이다. 정확한 식은 축평원 문의 또는 일별 이력으로 재현해야 안다. 평소가 계산식(로드맵 ②)에서 이 값을 쓸지 정할 때 다시 본다.

## 5. `grdNm` → 규격 분리 규칙

`grdNm` 하나에 등급과 원산지가 섞여 있다. **문자열 모양이 아니라 축종(`judgeKind`)으로 의미를 정한다.**

| 축종 | `grdNm` 값 | 뜻 | 우리 모델 |
|---|---|---|---|
| 4301 소 | `1+등급`, `1등급` | 등급 | **규격** (등급). 이름은 `등급`을 떼어 `1+`, `1`로 둔다 |
| 4401 수입 소고기 | `미국산`, `호주산` | 원산지 | **품종**을 가른다. 규격 아님. GLOSSARY의 품종 예 "호주산 등심"처럼, 원산지가 다르면 사용자가 다른 평소가를 기대하기 때문이다. 예: 4401-62-미국산 → 품종 "미국산 척아이롤" |
| 9903 계란 | `일반란` | 사육·생산 방식 | **규격** (기본값). 동물복지란·유정란은 이 출처에 없다 |
| 4304, 4402, 9901, 9908 | `구분없음` | 없음 | 품종의 **기본 규격** (`grade.is_default`) |
| (그 밖의 값) | | 처음 보는 값 | `source_code_map`에 `pending`으로 등록하고 운영자가 처리 |

- 원천 키는 `pipeline.md` 3-1의 형식을 그대로 쓴다: `ekape:{judgeKind}-{itemCd}-{grdNm}` (예: `ekape:4304-27-구분없음`, `ekape:4401-62-미국산`). 이 셋이 하루 안에서 행을 유일하게 정한다.
- **냉장·냉동**은 품목코드가 따로 있다 (수입 척아이롤 62 냉장, 68 냉동). 같은 품종의 규격으로 둘지 품종을 나눌지는 품종 목록(`p3-variety-catalog/01`)에서 정한다. 가격대가 크게 다르다 (10-18 미국산 냉장 4,514원, 냉동 2,839원).
- 계란 `XL30구`의 크기(XL)와 수량(30구)은 `itemNm`과 `unit`(`원/30구`)에서 읽는다. 기준 단위 환산 규칙에 넣는다.
- **순별·월별·연도별 기능은 `grdNm`이 코드로 온다** (돼지 `00`). 이 기능을 쓰게 되면 이름 대신 코드 매핑이 따로 필요하다 (11장).

## 6. 오류와 빈 응답

| 경우 | HTTP | 본문 | 처리 |
|---|---|---|---|
| 정상 | 200 | `resultCode 00` + item | |
| 해당 날짜 데이터 없음 (2010-01-15 등) | 200 | `resultCode 00` + `<items/>` | 0건. 당일 행이 없으면 실패로 보고 다시 받기 |
| 아직 안 올라온 날 (기준일 당일 오전) | 200 | `resultCode 00` + **평년 행만** | 위와 같음 (4장) |
| 날짜 형식 오류 (`standYmd=INVALID`) | 200 | `resultCode 99` + Oracle 오류 문구(`ORA-01841`, `OPENAPI.PKG_RTSAL`) | `resultMsg`를 로그·화면에 그대로 내보내지 않는다. 코드만 남긴다 (`samples/ekape/error-bad-date.xml`) |
| 인증키 오류 | 403 | 공공데이터포털 공통 오류 (`api-spec.md` 공통 사항) | |

HTTP 상태만 보지 말고 `resultCode`와 당일 행 유무를 함께 본다.

## 7. `regionPrc1~17` (시도별 가격): MVP 미사용

번호와 시도: 1 서울, 2 부산, 3 대구, 4 인천, 5 광주, 6 대전, 7 울산, 8 세종, 9 경기, 10 강원, 11 충북, 12 충남, 13 전북, 14 전남, 15 경북, 16 경남, 17 제주.

- **MVP는 전국 값(`ntslPrc`)만 쓴다.** 판정은 전국 기준이고, 지역 판정은 MVP 범위 밖이다.
- 원본(Storage의 gzip 응답)에는 남으므로 나중에 지역 시세가 필요하면 다시 계산할 수 있다.
- 쓸 때 주의할 점: 표본이 적은 품목은 시도 값이 빠지거나 몇 주째 같은 값이다 (9장). 시도 값은 2022년부터 있다.
- KAMIS 축산 응답의 시도별 값(`sgg_cd` 1101 서울 등)과 같은 숫자다 (8장).

## 9. 갱신 시각, 조사 주기, 갱신 지연

### 갱신 시각: D일분은 D일 16:30 이후, D+1일 10:10 이전에 올라온다

| 호출 시각 (KST) | 요청 기준일 | 결과 | 근거 |
|---|---|---|---|
| D일 16:30 (10월 초) | D | 평년 행만 | `pipeline.md` 1장 |
| 2026-10-12(월) 11:27 | 10-11(일) = D+1 | 당일 행 있음 | `samples/manifest.tsv` |
| 2026-10-19(월) 10:10 | 10-19 = D | 7개 축종 모두 **평년 행만** (27행) | 이번 실측 |
| 2026-10-19(월) 10:10 | 10-18(일) = D+1 | 당일 27행 + 평년 27행 | 이번 실측 |

- **정확한 시각은 아직 모른다.** 응답에 등록 시각 필드가 없고, KAMIS 축산 행의 `orgnl_reg_dt`도 비어 있어 거꾸로 알아낼 수 없다.
- 시각을 좁히려면 **D일 18:00, 21:00, D+1일 00:30, 03:00, 06:00, 08:00**에 `standYmd=D&judgeKind=4304&itemCd=27`을 한 번씩 부르면 된다 (6회. 당일 행이 처음 나온 시각이 답). 또는 수집을 시작한 뒤 `source_day.first_ok_at`을 2주 쌓는다 (`pipeline.md` 5-1).
- 지금 수집 일정(매일 06:40, D-1 + D-2·D-3 다시 받기)은 이 범위 안이라 확인 전에도 문제없다. 06:40에 D-1이 없으면 다음 날 D-2로 다시 받는다.

### 조사 주기와 휴일

- **2026년은 매일 값이 있다.** 토·일(10-11, 10-17, 10-18), 신정(01-01), 설날(02-17), 추석 연휴(09-24~26), 개천절(10-03), 한글날(10-09) 모두 당일 행이 있었다. 휴일이라고 비우지 않는다.
- **예전에는 공휴일이 비어 있다.** 2021-01-01, 2021-03-01, 2021-10-11(대체공휴일), 2020-01-01, 2015-01-01은 당일 행이 없고 평년 행만 있다. 과거분을 채울 때 빈 날은 정상이다. 언제부터 매일 조사로 바뀌었는지는 확인하지 않았다.
- **휴일에도 값이 바뀐다.** KAMIS로 받은 09-20~10-03 삼겹살 전국 값이 매일 달랐다 (추석 09-24 3,076 → 09-25 3,111 → 09-26 3,054). 휴일에 전날 값을 그대로 이어 쓰는 모습은 전국 값에서는 보이지 않았다.

### 갱신 지연 의심: 표본이 적은 품목

- **소 갈비(4301-50)는 1주일 넘게 같은 값이다.** 10-11, 10-14, 10-18의 1등급 `ntslPrc` 6,839원과 시도 값 13개가 모두 같다 (1+등급도 10-11과 10-14가 같다). 최고 10,000원, 최저 4,500원처럼 딱 떨어지는 값이 섞여 있다. 조사 표본이 적어 값이 이어지고 있는 것으로 보인다.
- 수입 양지(냉장) 미국산은 시도 3곳만 값이 있고, 수입 척아이롤(냉동)도 8~11곳뿐이다.
- 처리: 같은 원천 키의 `ntslPrc`가 N일(예: 7일) 넘게 똑같으면 `carried_over` 플래그를 달고 신뢰도를 낮춘다 (`pipeline.md` 3-3 `flags`). N은 판정 설계(②)에서 정한다.

## 12. 같은 서비스의 다른 기능

같은 주소 아래 `grade/…`에 순별·월별·연도별 기능이 있다 (`openapi-guide.txt` API 7~9). 2026-10-19에 돼지(4304)로 한 번씩 불러 봤다.

| 기능 | 요청 | 응답 | 평가 |
|---|---|---|---|
| 순별 `consumerPriceTenDays` | `standYm=202609` | 초·중·하순 가격(`ntslPrc_1~3`), 월평균, 같은 순의 평년(`avgYearPrc_1~3`) | 쓸 만하다. 순 단위 평년을 일별보다 적은 호출로 받을 수 있어, 평소가 계산식에서 평년을 순 단위로 쓰기로 하면 이것으로 충분하다 |
| 월별 `consumerPriceMonth` | `standYm=202609` | 월평균(`ntslPrc`), 월 평년(`avgYearPrc`) | 화면의 "지난달 대비"나 월별 추이에만 쓸 만하다. 일별에서 계산할 수 있어 MVP에는 필요 없다 |
| 연도별 `consumerPriceYear` | `standY=2025` | 연평균·최고·최저, `year=평년` 행 | 미사용. 판정에 쓰기에는 너무 거칠다 |

- 세 기능 모두 `grdNm`이 이름 대신 코드(`00`)로 온다. 쓰게 되면 코드 매핑을 따로 확인한다.
- 같은 서비스의 검수 확인 정보(`confirm/…`)와 재고량(`LPStock`)은 가격이 아니라서 보지 않았다. 재고량은 가격 이슈 신호 후보(확장 E4)로만 남긴다.

## 13. 스키마에 넘길 사실

| 항목 | 내용 |
|---|---|
| 자연키 | 당일 행: (`judgeKind`, `itemCd`, `grdNm`, `standYmd`). 평년 행: (`judgeKind`, `itemCd`, `grdNm`, **요청** `standYmd`) |
| `source_key` | `ekape:{judgeKind}-{itemCd}-{grdNm}`. `itemCd`는 축종 안에서만 유일하다 |
| 타입 | 코드는 문자열로 둔다 (`itemCd` `01`의 앞 0). 가격은 정수(원). 날짜는 `standYmd`를 date로 변환하되 `평년`은 date가 아니다 |
| 빈 값 | 시도 가격은 태그가 빠진다 → null |
| 단위 | 축종별로 고정: 소·돼지 100g, 닭 1kg, 계란 30구, 우유 1L. `unit` 문자열로 확인하고, 예상과 다르면 `price_per_base`를 null로 두고 경보 |
| scope | `ntslPrc` → `national`. 시도 값은 MVP 미사용 |
| 하루 행 수 | 당일 27 + 평년 27. 조합은 날마다 조금 달라질 수 있다 |
| 성공 판정 | `resultCode = 00` **그리고** 당일 행 1개 이상 |
| 등록 시각 | 원천 등록 시각 필드 없음 → `source_registered_at`은 null |
