# 품종 목록

Status: 확정 (2026-10-26). `.scratch/p3-variety-catalog/issues/01-variety-list.md`의 산출물이다. 운영 DB에 넣는 원본은 `packages/price-ingest/src/catalog/varieties.ts`(slug·원천 키)이고, 테스트가 이 표와 같은지 본다. 품종을 고치면 둘을 같이 고친다.

판정할 **품종**의 목록과 각 품종이 어느 출처의 어느 코드로 시세를 받는지 정한다. 용어는 [GLOSSARY.md](../../GLOSSARY.md). 입력은 [item-inventory.md](sources/item-inventory.md)(2026-10-19 실측)와 2026-10-19~23 KAMIS 가격 실측이다.

## 정한 규칙 (2026-10-26)

1. **신선식품만 판정한다.** 참가격 가공식품 386개는 수집은 계속하되 품종에 잇지 않는다(`product_variety_map.status = ignored`). 우유·계란은 KAMIS·축평원 시세가 있어 들어간다.
2. **사람이 하나의 식재료로 인식하면 한 품종이다.** 숫자 기준으로 자동으로 가르지 않는다. 사과 홍로·시나노골드는 사과 하나, 포도 캠벨얼리·거봉·샤인머스켓은 각각 다른 품종. 배추·무처럼 철마다 KAMIS 품종 코드만 바뀌는 것은 한 품종이다.
3. **원산지가 다르면 품종을 가르고, 보관 상태(냉장·냉동·염장)와 크기는 규격으로 둔다.** 한우 등심 / 미국산 갈비, 고등어(국산) 규격 냉장·염장.
4. **등급은 규격이고 기본 규격은 상품**(KAMIS `04`). 축산은 1+등급이 기본. 사과 상품 대 중품이 28~39% 차이라 섞지 않는다.
5. **기준 단위는 장 볼 때 생각하는 단위**: 개수로 사는 것은 1개(배추·무는 1포기·1개), 무게로 사는 채소·고기·수산은 100g, 쌀은 1kg, 계란은 30구, 우유는 1L. KAMIS 단위에서 나누기만 하면 되는 것은 바로 환산하고(10개 → 1개, 1kg → 100g), 개수와 무게를 바꿔야 하는 것(고등어 염장 1손, 참가격 갈치 100g)은 환산 기준이 정해질 때까지 기준 단위 가격을 비운다.
6. **실제 소매 데이터가 오는 것은 다 넣는다.** 화면에서 무엇을 먼저 보일지는 ③에서 정한다.
7. 축산의 대표 출처는 조합 단위 (pipeline 6-1): 두 출처에 다 있으면 축평원, KAMIS에만 있으면(한우 1++, 계란 등급란·10구, 닭 호수) KAMIS.

**커버 상태**: 충분 = KAMIS·축평원 매일 시세. 점포 = 참가격 상품이 있어 점포·업태별 판매가가 나온다. 부분 = 참가격 격주 판매가뿐.
