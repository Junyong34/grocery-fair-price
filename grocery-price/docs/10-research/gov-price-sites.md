# 정부·공공 가격정보 사이트 벤치마킹

정부가 이미 공개하는 가격 화면을 우리 출처 3개(KAMIS 일별, 축평원 소비자가격, 참가격)로 다시 만들 수 있는지, 그리고 그 밖에 쓸 만한 공공 출처가 있는지 조사했다. 조사일은 2026-10-19. 이 조사로 정한 할 일은 `.scratch/search-first-view/spec.md`에 있다.

용어는 [GLOSSARY.md](../../GLOSSARY.md)를 따른다. 정부 화면의 표기(예: "평균가격", "판매점")는 따옴표로 그대로 옮긴다.

## 1. 참가격 생필품 가격정보 화면

URL: `https://www.price.go.kr/tprice/portal/dailynecessitypriceinfo/priceiteminfo/getPriceItemInfoList.do`

### 결론: 대부분 다시 만들 수 있다

이 화면은 참가격 API(`ProductPriceInfoService`)를 그대로 화면에 옮긴 것이다. 2026-09-25 팔도 왕뚜껑(`goodId=1000`)으로 화면과 API를 맞춰 봤다.
- 점포 수 419곳이 저장 샘플 `price-by-good-1000.xml`의 419행과 같다.
- 업태별 점포 수(대형마트 115, 백화점 16, 슈퍼 284, 편의점 4)와 최저·최고가도 같다.
- 카테고리 메뉴의 `goodClassCode`와 품목 드롭다운 코드는 AL 분류 코드와 같은 값이다.

막히는 곳은 네 가지다.
1. **"6개월전", "1년전" 열은 API로 채울 수 없다.** API 과거 조회는 2026-06-12 조사분부터만 된다([api-spec.md](api-spec.md) 참가격 절). 화면은 2020년부터 고를 수 있다.
2. **"평균가격"은 점포 단순 평균이 아니다.** 판매처를 거쳐 2단으로 평균을 낸다(아래). API에는 판매처 필드가 없다.
3. **전통시장(TR) 업태는 API에 없다.** 업태 코드 BU에 TR이 없고, 점포 630곳 중 0곳이다. 화면도 "전통시장(0)"이라 지금은 문제가 되지 않는다. (TR은 정부 화면의 코드다. 다른 저장소의 DB 스키마에는 JM으로 적혀 있다, [api-spec.md](api-spec.md) 4장.) 신선식품의 전통시장 가격은 KAMIS로 본다 (2장 끝).
4. **상품 이미지는 API에 없다.**

### 화면 구성 (실측)

**검색 폼** (POST `getPriceItemInfoList.do`, 결과는 서버가 HTML로 그린다)
- 일자: 연·월·일 선택. 조사일 목록은 `getInspectYear.do`, `getInspectMonth.do`, `getInspectDay.do`가 JSON으로 준다.
- 업태: LM 대형마트, DP 백화점, SM 슈퍼마켓, TR 전통시장, CS 편의점
- 지역 `entpAreaCode`(18개 시도), 점포 `entpId`
- 품목 `goodSmlclsCode`(AL 소분류), 상품 `goodId`
- 정렬(최저가순, 최고가순), 목록 수 10~200개

**결과 영역**
- 업태 탭: 전체(N)와 업태별 점포 수
- 요약표 "전국 전체 판매점 평균": 평균·최고·최저 × 전체·업태 5개
- 점포 목록: 지역, 점포, 상품명, 판매가(`990원/110g`, `900원/100g`), 2주전·1개월전·6개월전·1년전(금액과 등락률), 5개 시점 꺾은선 차트, 할인 아이콘, 지도 팝업
- 안내 문구: "조사 시점: 격주 수요일(백화점, 편의점), 목요일(대형마트, 슈퍼마켓)"

필터를 여러 개 고른 뒤에야 상품 하나의 결과가 나온다. 상품을 고르지 않으면 규칙을 알 수 없는 상품 하나가 먼저 보인다(10-09 채소 조회 시 양파만 나옴).

### 화면 요소 → API 대응표

| 화면 요소 | 출처 · 필드 | 판정 |
|---|---|---|
| 카테고리 메뉴 13개 | AL 중분류 (`030201000` 등) | 그대로. 코드는 같고 이름만 다르다(정육·난류 = 축산물, 생선류 = 수산물 등). AL `030305000` 기타용품은 메뉴에 없다 |
| 품목 드롭다운 | AL 소분류 (`highCode` = 중분류) | 그대로. 곡물가공품 24개가 코드까지 같다 |
| 상품 드롭다운 | `getProductInfoSvc` `goodSmlclsCode`·`goodId`·`goodName` | 그대로. 화면 코드와 `goodId`가 같다 |
| 조사일 목록 | `goodInspectDay` | 계산. API에 목록 기능이 없어 금요일마다 호출해 빈 응답이 아닌 날을 모은다 |
| 업태 필터·탭 건수 | 점포 `entpTypeCode`를 `entpId`로 조인 | 그대로. TR은 데이터 없음 |
| 지역 | `entpAreaCode` + AR 코드 | 그대로. 18개 시도 이름이 같다 |
| 점포 | `entpId`, `entpName` | 그대로 |
| 판매가, `/110g` | `goodPrice`, `goodTotalCnt`·`goodTotalDivCode` | 그대로 |
| `900원/100g` | `goodPrice ÷ goodTotalCnt × goodBaseCnt` | 계산. 990/110×100 = 900으로 화면과 같다 |
| "평균가격" | 판매처별 2단 평균 | 계산. 점포→판매처 매핑표가 필요하다 |
| 최고·최저 | `goodPrice` max·min | 계산. 화면과 같다 |
| 2주전, 1개월전 | 이전 조사일의 같은 `entpId`·`goodId` | 계산. 2026-06-12 이후만 |
| 6개월전, 1년전 | 없음 | API로는 불가 |
| 등락률 | (현재 − 과거) ÷ 과거. 990 대 1,150 → −13.9% 확인 | 계산 |
| 차트(5개 시점) | 위 다섯 값 | 지금은 3개 시점까지만 |
| 할인 아이콘 | `goodDcYn`, `goodDcStartDay`·`goodDcEndDay`, `plusoneYn` | 그대로. 필드가 행마다 오지 않는다(419행 중 2행) |
| 지도 | `xMapCoord` = 위도, `yMapCoord` = 경도 | 그대로 |
| 정렬, 페이지 나누기 | API에 페이지 나누기가 없어 전부 받는다 | 우리 쪽에서 처리 |
| 상품 이미지 | 없음 | 불가 |

### "평균가격" 계산 방식 (역산)

| 업태 | 판매처별 평균 | 2단 평균 | 점포 단순 평균 | 화면 |
|---|---|---|---|---|
| 대형마트 | 이마트 1,280, 농협 1,200 | 1,240 | 1,279 | 1,240 |
| 슈퍼마켓 | 롯데슈퍼 1,388.2, GS더프레시 1,304.6 | 1,346.4 | 1,352 | 1,346 |

- 업태 평균 = 업태 안 판매처별 평균의 평균
- 전체 평균 = 데이터가 있는 업태 평균의 평균: (1,240 + 1,500 + 1,346 + 1,600) ÷ 4 = 1,421.5, 화면 1,422

판매처는 `entpName` 앞부분(이마트, 롯데슈퍼, GS더프레시, CU 등)으로 나눠 맞췄다. 점포 단순 평균을 쓰면 화면과 몇십 원 차이가 난다.

### 조사 주기

- API 조사일은 격주 금요일이지만 실제 조사는 그 주 수·목요일이다(화면 안내 문구). `inputDttm`이 조사일보다 0~2일 이른 이유다. 다만 5~7일 뒤에 입력되는 조사일도 있다 ([chamgagyeok.md 5-3](../30-data/sources/chamgagyeok.md)).
- **10-09 조사는 있다.** 10-12에는 비어 있어 한글날로 추정했지만, 10-19에 다시 호출하니 `goodId=1000`의 10-09분이 437행 왔다. 일정이 빠진 것이 아니라 **등록이 늦었다** (10-09분의 `inputDttm`이 10-15~16). 조사일 직후 한 번만 받으면 놓칠 수 있다.

### KAMIS·축평원으로 메울 수 있는가

- **이 화면 자체는 못 메운다.** 화면의 신선식품(정육·난류, 채소, 생선류, 곡물)도 모두 참가격 상품(예: `배추(1.5~2kg)`)의 점포별 판매가다. KAMIS는 22개 도시 시장의 소매 시세, 축평원은 17개 시도 시세라 점포 행, 업태, 판매처 평균을 만들 수 없다.
- **보조로는 쓸 만하다.** KAMIS는 1996년부터 이력이 있어 1년 전 시세를 계산할 수 있고, 축평원은 평년 행을 함께 준다. 다만 판매가와 시세는 성격이 달라 화면에서 구분한다.

### 2-1. 지자체 물가조사(15109061) 실측 (2026-10-19)

- data.go.kr 항목은 API 유형이 "LINK"다. data.go.kr 키로 부르지 않고, 농림축산식품 공공데이터포털(data.mafra.go.kr, `data_id=20221205000000002360`)에서 별도 키를 받아 부른다.
- 요청: `http://211.237.50.150:7080/openapi/{API_KEY}/{xml|json}/Grid_20221205000000000651_1/{START}/{END}?EXAMIN_DE=YYYYMMDD`. 한 번에 최대 1,000행. 공개 샘플 키 `sample`은 5행까지.
- 실측(샘플 키): 2022-12-29 3,162행, 2022-12-30 3,178행. 2023-01-05, 2023-01-06, 2024-01-04, 2025-01-03, 2026-09-17, 2026-10-15, 2026-10-16은 모두 0행. 명세 제목도 "(1998-01-03 ~ 2022-12-30)", 업데이트 주기 "주기없음"이다.
- 빈 날도 `INFO-000`(정상)으로 온다. 명세의 `INFO-200`(데이터 없음)은 오지 않았다.
- 2022년까지의 응답에는 조사 구분(`EXAMIN_NM` 소비자가격·도매가격), 표준 품목·품종 코드, 등급, 단위, 당일·전일 가격, 지역, 점포 이름(경동시장, 롯데마트 잠실점, 홈플러스 금천점)이 있었다. 형식은 쓸 만하지만 갱신이 끊겼다.
- 이 저장소 샌드박스에서는 `211.237.50.150:7080`에 curl이 시간 초과로 닿지 않았다. 다른 경로(wigolo fetch)로는 응답이 왔다. 다시 부를 때 참고한다.

전통시장 축은 새 출처 없이 **KAMIS 소매**로 채운다. KAMIS 시장 이름(`mrkt_nm`)에 실명 전통시장(경동, 부전, 칠성, 양동, 동문 등)과 익명 대형유통("A-유통" 등)이 함께 온다 (배추 14일 샘플: 조사 시장 48곳(코드 기준) 중 실명 16곳, `X-유통` 32곳. 이름 기준으로는 15개·9개. [kamis.md 5-2](../30-data/sources/kamis.md)). 서울 열린데이터광장 OA-1170(서울 한정, 매주)은 보조 후보로만 둔다.

크롤링은 하지 않는다([ADR 0001](../adr/0001-public-data-and-reports-over-crawling.md)). 위 출처는 모두 Open API나 파일데이터가 있다.
