# 02. 데이터 확보와 법적 리스크

> 법률 자문이 아니다. 공개 자료를 정리한 것이므로 서비스 시작 전에 변호사 검토를 받는다.
> 표기: **미확인** = 출처로 확인하지 못함, **의견** = 판례·조문에서 끌어낸 해석.

## 1. 결론 먼저

| 데이터 확보 방식 | 리스크 | 판단 |
|---|---|---|
| 공공데이터 (KAMIS, 참가격, 축평원) | 매우 낮음 | **주 데이터원** |
| 사용자 제보 (가격 입력, 가격표 사진) | 낮음 (개인정보만 주의) | **공백 보완 + 참여 유도** |
| 쇼핑몰·마트 제휴, 상품 피드 | 낮음 (계약 필요) | 성장 단계 목표 |
| 네이버 쇼핑 / 쿠팡 파트너스 API | 약관 충돌 | 실시간 표시·링크용으로만 검토. 이력 저장 불가 |
| 쇼핑몰 크롤링 | 중~높음 | 주 데이터원으로 쓰지 않음 |

## 2. 법적 쟁점

| 근거 | 핵심 내용 |
|---|---|
| 저작권법 제93조 (DB제작자 권리) | DB의 "전부 또는 상당한 부분" 복제 시 침해. 일부라도 반복적·체계적 복제로 상당 부분과 같은 결과면 침해 (대법원 2021도1533) |
| 부정경쟁방지법 (파)목 성과물 도용 | 상당한 투자로 만든 성과를 무단 사용. 야놀자 민사에서 인정 |
| 부정경쟁방지법 (카)목 데이터 부정사용 | 2022.4. 시행. 형사처벌은 보호조치 무력화 도구 제공에 한정. 일반 크롤링은 민사 책임 |
| 정보통신망법 제48조 | 기술적 보호조치 등 객관적 사정으로 접근권한 판단. 약관만으로는 접근 제한으로 보지 않음 |
| 형법 제314조 (업무방해) | 실제 정보처리 장애가 발생해야 성립 |

- **개별 가격**은 사실 정보라 저작물로 보기 어렵다 (의견).
- 그러나 **가격이 축적된 DB**는 보호 대상이 될 수 있다. 야놀자 민사 사건에서 복제된 DB에 "원래 금액, 할인 금액"이 포함돼 있었다.

## 3. 판례

| 사건 | 결과 | 시사점 |
|---|---|---|
| 잡코리아 v 사람인 | 서울고법 2016나2019365: DB권 침해, 배상 | 기계적 대량 복제 후 자사 게재 |
| 야놀자 v 여기어때 (형사) | 대법원 2021도1533, **무죄** 확정 (2022.5.) | 보호조치 없음, 상당 부분 아님, 장애 없음 |
| 야놀자 v 여기어때 (민사) | 서울중앙지법 2021: **10억 배상** (항소심 결과 미확인) | 조직적·지속적 복제, IP 차단 우회, 경쟁관계 |
| 네이버 v 다윈중개 (2024.9.) | DB권 침해, 7천만 원 배상 | 이용자 이탈로 인한 손해 인정, 약관 금지 조항 |

**형사는 무죄여도 민사로 질 수 있다.** 이것이 가장 중요한 교훈이다.

robots.txt 허용이 약관상 허용을 뜻하지는 않는다. 약관 본문은 별도로 확인해야 한다.

## 5. 공식 API의 제약

- **네이버 쇼핑 검색 API**: 하루 25,000회, 한 번에 100건.
  - 약관(2026-10-07 개정)상 허용 범위를 넘는 **저장(캐시 포함) 금지**
  - 결과 화면과 함께 광고 노출 금지
  - 이용자에게 대가를 받는 것 금지
  - → 가격 이력 저장과 충돌. 쓰려면 네이버와 별도 협의가 필요하다 (의견).
- **쿠팡 파트너스 API**: 데이터 복제·저장·전송 금지(제5조), 스크레이퍼 금지(제8조). 실제 검색 호출 한도가 매우 낮다는 개발자 후기가 있다 (2차 출처).
- 활용 가능성: 품목 상세 화면에서 **"지금 온라인 판매가 보기" 실시간 조회 + 원본 링크**로만 쓰는 방식. 이 경우에도 광고·수익 모델과 충돌하는지 약관 검토가 필요하다.

## 6. 공백을 메우는 전략

공공데이터에 없는 것: 홈플러스·롯데마트 매장 가격, 온라인몰 가격 ([public-data-survey.md](public-data-survey.md) 참고).

1. **사용자 제보 (크라우드소싱)**
   - 판정 화면의 "내가 본 가격 입력"이 그대로 제보 데이터가 된다. 판매처·점포·가격·규격을 선택해서 입력한다.
   - 가격표·영수증 사진 OCR은 2단계. 영수증에는 카드번호 일부 등 개인정보가 섞이므로 저장 범위를 최소화한다.
   - 제보 데이터는 신뢰도를 낮게 시작하고, 여러 건이 일치하면 올린다.
2. **제휴**: 트래픽이 생기면 마트·온라인몰에 상품 피드(EP) 제휴를 제안한다. 업계에서 흔한 방식으로 알려져 있지만 근거 자료는 미확인이다.
3. **제한적 수집 (최후 수단, 변호사 검토 후)**: 판례 기준을 거꾸로 적용한 원칙이다 (의견).
   - 품목 수십 개, 대표 SKU만 수집 (상당 부분 회피)
   - 하루 1~2회, 낮은 빈도
   - robots.txt·로그인·캡차·IP 차단 우회 금지, 비공개 앱 API 호출 금지
   - 출처 표기와 원본 링크 제공 (이용자를 원본으로 보냄)
   - 원본 서비스를 대체하는 형태로 보이지 않게 설계

## 7. 변호사 자문 시 물어볼 것

- 사용자 제보 가격(특정 점포명 포함)을 공개하는 것에 문제가 있는지
- 네이버 쇼핑 API를 실시간 표시용으로만 쓰는 경우 약관 위반 여부
- robots.txt가 허용된 사이트에서 소량 수집하는 경우의 리스크 수준
- 광고·제휴 수익 모델이 공공데이터 라이선스(공공누리 1유형)와 충돌하지 않는지
