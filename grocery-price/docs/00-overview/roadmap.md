# 로드맵

각 단계는 **완료 기준**을 모두 충족해야 다음 단계로 넘어간다. 앞 단계에서 정한 내용이 뒤 단계에서 틀린 것으로 드러나면, 해당 단계 문서를 고치고 변경 사유를 남긴다.

## 전체 흐름

```
P0 기획·조사 ✅
 │
 ├─ 데이터 트랙 (핵심 경로) ─────────────────────────────
 │  P1 도메인 모델링
 │  P2 데이터 소스 명세 (공공데이터 포맷·규격)
 │  P3 표현 가능 값 카탈로그 (소스 단위)
 │  P4 어댑터 · 통합 데이터 모델
 │  P5 표현 설계 (지표 · 위젯)
 │
 ├─ 기반 트랙 ─────────────────────────────────────────
 │  P6 기술 아키텍처 (스택 · DB · 배치 · 배포)
 │  P7 디자인 시스템 (원칙 · 토큰 · UI 라이브러리)
 │
 ├─ 화면 트랙 ─────────────────────────────────────────
 │  P8 정보구조 · 페이지 설계 (사이트맵 · 히어로 · 메뉴 · 콘텐츠 · URL)
 │  P9 SEO · 분석 설계 (메타 · 구조화 데이터 · GA4 · Search Console)
 │  P10 디자인 시안
 │
 └─ P11 구현 · 배포 · 등록
```

- **P1~P5는 순서대로 진행한다.** 뒤 단계가 모두 여기에 의존한다.
- P6과 P7은 P5가 끝나면 병행할 수 있다.
- P8과 P9는 함께 진행한다. URL 구조와 페이지 유형이 곧 SEO 설계이기 때문이다.
- P6의 렌더링 방식(정적 생성/서버 렌더링)은 P9의 SEO 요구를 입력으로 받는다. P6에서는 P5 결과로 페이지 유형과 개수를 먼저 추정해 둔다.

## 단계별 정의

### P1. 도메인 모델링

- **목표**: 서비스가 다루는 개념과 경계를 확정한다. 이후 모든 단계가 이 언어를 쓴다.
- **산출물**
  - `GLOSSARY.md`: 용어 정의, 피해야 할 동의어
  - `docs/20-domain/domain-model.md`: 개념 관계, 불변 규칙, 시나리오 검증 표
  - MVP 범위 원칙: 공공데이터 + 제보. 구체적인 품종 목록은 데이터 보유 여부를 확인한 뒤 P3에서 확정
- **완료 기준**
  - P1 범위의 열린 질문이 모두 결정되고, 남은 질문은 담당 단계가 지정됨 ([domain-model.md](../20-domain/domain-model.md) 10장)
  - 같은 문서 8장의 시나리오가 모두 모델로 설명됨
  - 화면·문서에 나오는 모든 도메인 용어가 용어집에 있음

### P2. 데이터 소스 명세

- **목표**: 공공데이터의 실제 포맷과 규격을 필드 단위로 확정한다.
- **선행 작업 (사용자)**: 공공데이터포털·KAMIS API 키 발급
- **산출물**: `docs/30-data/sources/{kamis,chamgagyeok,ekape}.md`
  - 엔드포인트, 요청 파라미터
  - 응답 필드: 이름, 타입, 단위, 빈 값 여부, 예시값
  - 코드 체계, 갱신 주기·시각, 호출 한도, 라이선스와 출처 표기 문구
  - 실호출 응답 샘플 → `reference/public-data/samples/`
- **보조 소스 조사**: `docs/30-data/sources/context.md`
  - 가격 이슈: 기상청 특보·관측, 가축 질병 발생 현황, 뉴스 키워드 수집 경로(뉴스 검색 API, 언론사 RSS, 뉴스 빅데이터 서비스)와 각 약관
  - 제철: 농정원 제철 농식품, 해수부 이달의 수산물
- **완료 기준**
  - 주 소스 3개(KAMIS, 참가격, 축평원)의 모든 응답 필드가 도메인 개념에 연결되거나 "미사용"으로 표시됨
  - [public-data-survey.md](../10-research/public-data-survey.md) 4장의 "검증 필요" 항목이 모두 해소됨

### P3. 표현 가능 값 카탈로그

- **목표**: 각 소스로 무엇을 보여줄 수 있고 무엇을 못 보여주는지 확정한다.
- **산출물**: `docs/30-data/display-catalog.md`
  - 소스별로 "그대로 표시 / 계산해서 표시 / 표시 불가" 표
  - MVP 품종 목록 (데이터가 실제로 있는 품종 기준)
- **완료 기준**
  - [product-concept.md](product-concept.md) 4장의 표시 항목 전부가 "가능 / 조건부 / 불가"와 근거 소스로 판정됨
  - MVP 품종마다 시세를 주는 출처가 하나 이상 있음

### P4. 어댑터 · 통합 데이터 모델

- **목표**: 서로 다른 소스를 하나의 통합 데이터로 만드는 규칙을 정한다.
- **산출물**: `docs/30-data/canonical-model.md`, `docs/30-data/adapters.md`
  - 통합 데이터 모델 (논리 수준, 특정 DB와 무관)
  - 소스별 변환 규칙: 필드 매핑, 단위 환산, 원천 코드 → 품목 매핑, 행사 처리, 중복·이상치 처리, 정정 데이터 처리(KAMIS 익일 재수집)
- **완료 기준**
  - 소스 3개의 실제 샘플 응답을 통합 모델로 변환한 예시 표가 있음
  - 변환할 수 없는 케이스가 목록으로 정리되고 처리 방침이 있음

### P5. 표현 설계 (지표 · 위젯)

- **목표**: 통합 데이터로 계산할 지표와 화면 위젯을 정의한다.
- **산출물**: `docs/30-data/metrics.md`, `docs/30-data/widgets.md`
  - 지표: 기준가, 판정, 변동률, 신뢰도의 계산식
  - 위젯: 신호등, 3점 비교, 추이 차트, 할인 배지, 오늘 싼 식자재 순위 등. 각 위젯의 입력 데이터, 계산 방식, 데이터가 부족할 때의 표시 규칙
- **완료 기준**: 모든 위젯이 통합 모델 필드만으로 계산 가능하고, 데이터 부족 시 동작이 정의됨

### P6. 기술 아키텍처

- **목표**: 스택, 데이터베이스, 배치, 배포 방식을 정한다.
- **산출물**: `docs/40-architecture/` 문서, 주요 선택은 `docs/adr/`에 기록
  - 데이터 볼륨 추정 (품목 수 × 소스 × 일수)
  - 렌더링 방식 (SEO 대상 페이지 수 기준)
  - 배치 스케줄러, 호스팅, 월 비용 추정
- **완료 기준**: 프론트엔드, 백엔드·배치, DB, 호스팅 선택이 모두 ADR로 근거와 함께 기록됨

### P7. 디자인 시스템

- **목표**: 화면을 일관되게 만들 기반을 정한다.
- **산출물**: `docs/50-design-system/`
  - 디자인 원칙
  - 토큰: 색(판정 3색, 차트 색 포함), 타이포, 간격, 반경, 그림자. 라이트/다크 모두
  - UI 라이브러리 선정 (ADR)
  - 아이콘·일러스트 스타일 (이미지 전략과 연결)
- **완료 기준**
  - 토큰 표가 확정됨
  - 판정 색이 색맹 사용자에게도 구분됨 (색 + 아이콘 + 문구 3중 표시)
  - 명도 대비 기준을 통과함

### P8. 정보구조 · 페이지 설계

- **목표**: 어떤 페이지가 몇 개 있고 각각 무엇을 하는지 정한다.
- **산출물**: `docs/60-pages/`
  - 사이트맵, 페이지 목록
  - 페이지별 목적, 주요 사용자 행동, 사용하는 위젯(P5), URL
  - 히어로 화면, 글로벌 메뉴, 페이지별 콘텐츠 블록 구성
  - 와이어프레임
- **완료 기준**: 모든 페이지가 목적·핵심 행동·위젯·URL을 갖고, 와이어프레임이 있음

### P9. SEO · 분석 설계

- **목표**: 검색 유입과 측정 체계를 설계한다.
- **산출물**: `docs/70-seo-analytics/`
  - 키워드 전략 (예: "애호박 가격", "삼겹살 시세")
  - 페이지 유형별 메타·OG 템플릿, 구조화 데이터, sitemap, robots, 내부 링크 규칙
  - GA4 이벤트 목록, Search Console 등록 체크리스트
- **완료 기준**: 모든 페이지 유형에 메타 템플릿이 있고, 핵심 사용자 행동이 이벤트로 정의됨

### P10. 디자인 시안

- **목표**: 와이어프레임에 토큰을 입혀 실제 화면으로 만든다.
- **산출물**: 핵심 화면 시안 (품목 판정 화면, 홈, 제철, 오늘 싼 식자재 등)
- **완료 기준**: 핵심 화면 시안이 승인됨

### P11. 구현 · 배포 · 등록

- **목표**: 만들고, 배포하고, 검색엔진과 분석 도구에 등록한다.
- **산출물**: `docs/90-delivery/` 구현 마일스톤, 배포 절차서
- **선행 작업 (사용자)**: 도메인 구매, GA4·Search Console 계정
- **완료 기준**: 운영 배포 완료, GA4 수집 확인, Search Console에 sitemap 제출

## 확장 단계 (MVP 출시 이후)

1차 데이터셋은 공공데이터로 만든다. 이후 아래 순서로 데이터 범위를 넓힌다.

### E1. 온라인몰 데이터

- **목표**: 온라인몰 판매가를 합법적으로 가져올 방식과 수집 주기를 정한다.
- **검토할 것**
  - 확보 방식: 제휴·상품 피드, 공식 API의 실시간 표시, 제한적 수집 (각각의 법적 검토는 [data-sourcing-legal.md](../10-research/data-sourcing-legal.md))
  - 수집 주기: 품종별 가격 변동성과 온라인몰의 가격 변경 빈도를 근거로 정한다
  - 배송비, 멤버십 가격, 최소 주문 금액을 판매가에 반영하는 규칙
- **완료 기준**: 온라인몰별 확보 방식·주기가 ADR로 기록되고, P4 어댑터에 온라인몰 변환 규칙이 추가됨
