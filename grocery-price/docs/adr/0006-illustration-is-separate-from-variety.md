# 그림은 품종과 따로 존재하고, 화면 데이터가 그림 ID를 가리킨다

그림은 그림 ID를 가진 독립된 것이다. 제철 품종, 이유식 재료, 전통 음식, 회 데이터가 각자 그림 ID를 가리킨다. 품종 ID와 그림 ID가 같을 때는 적지 않고, 다를 때만 품종 원본(`packages/seasonal/src/data/food-registry.json`)에 그림 ID를 적는다. 웹에 내보내는 그림은 "그림 검수를 마쳤고 어느 화면 데이터든 가리키는 그림"이다. 2026-11-12에 정했다 (`.scratch/docs-and-illustration-cleanup/spec.md`).

이전에는 품종 목록(`prototypes/` 안의 `foods.json`)과 그림 목록(`build/catalog.json`)을 이름으로 대조해 품종 ID를 그림 ID로 삼았다. 이름이 안 맞는 것은 `build-foods.mjs`의 `DRAWN_AS`·`NEW_IDS`로, 제철에 없는 그림은 `sync-food-images.mjs`의 `CANDIDATE_FOOD_IDS`와 이유식 화면의 그림 목록으로 따로 덮었다.

이유: 그림은 제철 품종보다 넓게 쓰인다. 이유식 재료에는 제철 품종인 것과 아닌 것이 섞여 있고, 한 그림을 두 품종이 쓰기도 한다(대하는 새우 그림, 참홍어는 홍어 그림). 그림 검수와 제철 검증은 서로 다른 판정이라, 그림을 품종의 속성으로 두면 "그림은 됐는데 제철은 모른다"를 표현할 수 없어 예외 목록이 늘어난다.

## 고려한 대안

- **그림을 품종의 속성으로 둔다**: 파일이 하나로 끝난다. 하지만 제철에 없는 이유식 재료를 품종 원본에 "달력에 안 나오는 품종"으로 넣어야 하고, 제철달력 목록에 품종이 아닌 것이 섞인다.
- **그림 검수를 마친 그림은 전부 내보낸다**: 규칙이 가장 단순하고 그림 생성과 화면 연결이 서로 기다리지 않는다. 하지만 어느 화면에도 안 나오는 그림이 운영 사이트에 올라가고, 용도를 정하지 않은 채 쌓인다. 사용자가 어드민에서 용도를 직접 정하기로 해서 택하지 않았다.

## 결과

- 새 그림은 용도가 정해지기 전까지 웹에 없다. 그래서 그림 어드민은 저장소의 웹 SVG가 아니라 `prototypes/` 안의 미리보기를 읽어 보여 준다.
- 그림 검수 상태는 그림 폴더의 `art.json`에, 제철 검증 근거는 품종 원본에 둔다. 두 기록은 서로를 읽지 않는다.
- `prototypes/`는 Git에 없으므로 그림 원본과 그림 검수 상태는 한 기기에만 있다. 저장소에는 동기화가 쓰는 `PROVENANCE.md`가 남는다.
- 품종 ID는 URL과 기기에 저장된 먹음 기록의 키라 그대로 둔다. 그림을 다른 것으로 바꿔도 품종 ID는 바뀌지 않는다.
