# 인쇄물 PDF는 비공개 Cloudflare R2에 두고, 우리 주소의 짧은 서명 링크로만 내준다

운영자가 어드민에서 만든 에디션 PDF는 **비공개 Cloudflare R2 버킷**에 올린다. 사용자는 R2 주소를 직접 보지 못한다. `/seasonal/downloads/[에디션]/[용지]` 같은 우리 Route Handler가 수명 약 60초의 presigned URL을 만들어 302로 넘긴다. 우리 주소의 응답은 `X-Robots-Tag: noindex`다(robots.txt Disallow는 쓰지 않는다: 이 저장소는 noindex로만 막는다, `shared/seo/pages.ts`). 색인되는 것은 다운로드 목록과 에디션 페이지뿐이다.

이유:

- **크기**: 2026-10-29 실측에서 월간 달력 PDF가 A4 7.45MB, A3 13.45MB였다(포스터·연간 한 장은 1~2.5MB). 에디션 15개, A4만 올려도 다운로드가 월간 달력에 몰리면 트래픽이 크다.
- **Supabase가 아닌 이유**: 가격 DB가 이미 같은 무료 프로젝트를 쓰고 있어 쿼터 여유가 없다. Storage egress 무료 한도(월 5GB)는 월간 달력 A4 약 670회면 닿고, 다운로드가 가격 서비스의 쿼터를 깎는다. R2는 egress가 무료다.
- **`public/`(빌드 산출물)이 아닌 이유**: PDF를 git에 커밋하면 다시 만들 때마다 기록이 무거워진다. 지금 `.gitignore`가 PDF를 제외하므로 배포본에 들어가지도 않는다.
- **우리 주소를 거치는 이유**: (1) 링크가 퍼져도 60초 뒤 무효다. (2) 나중에 광고를 본 뒤 내려받게 할 때 검사를 끼울 자리가 된다. (3) 저장소를 바꿔도 사용자 링크가 그대로다. (4) 다운로드 수를 에디션별로 셀 수 있다. 302는 검색 로봇도 따라가지만 원래 주소를 기준으로 삼으므로 문제가 없다.
- **커스텀 도메인 없이**: S3 호환 API의 presigned URL만 쓰므로 DNS를 Cloudflare로 옮기지 않는다. 호스팅을 Vercel로 할지 정하지 않았어도 Next Route Handler가 도는 곳이면 된다.

## 고려한 대안

- **Next `public/`에 두고 CDN이 내려준다**: 가장 단순하지만 위 git 문제와, URL이 영구 공개라 광고 게이트를 붙일 수 없는 문제가 있다.
- **Supabase Storage + signed URL**: 구조는 같고 계정이 늘지 않지만 위 쿼터 문제로 뺐다. PDF가 1~2MB로 줄어도 가격 데이터와 쿼터를 나누는 문제는 남는다.
- **R2 공개 버킷 + Cloudflare 캐시·rate limit**: Cloudflare DNS에 도메인이 있어야 하고, URL이 고정 공개라 게이트를 붙일 수 없다.

## 결과

- 키 두 벌: 쓰기 키는 운영자 로컬 `.env`(루트, 어드민은 운영에 없다), 읽기 전용 키는 운영 환경변수.
- 객체 키는 로컬 경로와 같은 `downloads/<id>/<paper>.pdf`다(`objectKey`). 다시 생성하면 덮어쓴다. 연도 · 종류 폴더는 두지 않는다(종류는 id에 있고, 연도는 바뀔 수 있다).
- rate limit은 처음에 두지 않는다. R2 읽기 요청 무료 한도(월 1,000만 건)가 넉넉하다. 악용이 보이면 Route Handler에 더한다.
- 에디션 목록(`manifest.json`)은 R2가 아니라 git에 커밋하고 배포로 반영한다. 목록 화면은 정적으로 남는다.
